# 화면 점검

기존 화면이 기본 품질 규칙을 지키는지, 쓰인 UI 패턴이 상황에 맞는지 점검한다. 기본은 점검만 하고 파일을 바꾸지 않는다.

## 지식 위치

- 품질 규칙: `${CLAUDE_PLUGIN_ROOT}/references/quality-rules.md` (Q01~Q16)
- 색인: `${CLAUDE_PLUGIN_ROOT}/references/index.md`
- 간격 수치: `${CLAUDE_PLUGIN_ROOT}/references/spacing.md`
- 변수가 치환되지 않으면 이 스킬 폴더 기준 `../../`를 앞에 붙인다.

## 절차

### 1. 대상과 방법 정하기
- 대상: 파일, 컴포넌트, 실행 중인 화면(URL), 스크린샷 중 무엇인지 확인한다. 대상 레포의 `CLAUDE.md`와 `AGENTS.md`를 읽고 디자인 시스템과 토큰이 있으면 그것을 기준으로 삼는다.
- 실행 화면을 볼 도구(브라우저 자동화, 스크린샷 도구)가 있으면 실제 렌더를 본다. 데스크톱 폭과 모바일 폭(약 390px), 가능하면 다크 모드까지 확인하고 콘솔 오류를 본다.
- 도구가 없으면 코드로 점검하고 "렌더를 직접 보지 못했다"고 보고서 맨 위에 밝힌다. 이 경우 대비 값은 코드의 색 값으로 계산하고, 렌더에서만 보이는 문제(겹침, 잘림, 정렬)는 확인하지 못했다고 쓴다.
- 스크린샷이면 그림에서 보이는 것만 점검하고 보이지 않는 것(상태, 키보드, 반응형)은 확인하지 못했다고 쓴다.

### 2. 점검
1. `quality-rules.md`의 Q01~Q16을 모두 훑는다. 각 규칙의 "확인 방법"대로 확인한다.
2. 화면에 쓰인 UI 패턴(내비게이션, 알림, 입력, 로딩, 빈 화면 등)을 목록으로 뽑는다. `index.md`로 해당 레퍼런스 항목을 찾아 "언제"와 "피할 때"에 비춰 이 상황에 맞는지 본다.
3. 헷갈리는 짝의 오용을 특별히 본다. 예: 설정이 즉시 적용되는데 체크박스, 되돌려야 하는데 토스트, 짧은 로딩에 전체 화면 스피너, 모바일 단순 선택지에 모달, 플레이스홀더만 있는 입력 칸. 기준은 `confusable-pairs.md`.
4. 상태 누락(hover, pressed, focus, disabled, loading, error, empty)과 긴 콘텐츠, 0건에서의 모습을 본다.
5. 대상 레포에 디자인 시스템이나 토큰이 있으면 거기서 벗어난 값을 지적한다.

### 3. 보고
지적은 심각도 순(높음, 중간, 낮음)으로 정렬한다. 각 지적의 형식:

```
[높음] <한 줄 제목>
- 위치: <파일:줄 또는 화면 영역>
- 문제: <무엇이 어떻게 문제인지, 가능하면 측정값>
- 근거: <레퍼런스 파일과 항목 이름 또는 규칙 번호>
- 수정: <고치는 방법>
```

심각도 기준:
- 높음: 사용을 막거나 접근성을 해치는 문제(대비 부족으로 읽을 수 없음, 키보드 불가, 터치 영역이 24px 미만(Q02), 필수 상태 누락으로 막힘, 패턴 오용으로 데이터 손실 위험).
- 중간: 사용은 되지만 혼란이나 어색함을 주는 문제(터치 영역 24~43px, 간격과 반경 불일치, 주 행동이 둘, 오류 문구 불친절, 패턴이 상황에 안 맞음).
- 낮음: 다듬기 수준(미세한 정렬, 아이콘 크기 차이, 모션 속도).

보고서 규칙:
- 잘된 점은 한두 줄만 쓴다. 지적이 없으면 "지적할 문제가 없습니다"라고 쓰고, 확인하지 못한 항목을 함께 적는다.
- 확인한 것과 추측한 것을 구분한다. 확인하지 못한 항목은 목록으로 밝힌다.
- 규칙 번호만 나열하지 말고 이 화면의 구체적인 요소와 값으로 쓴다.

### 4. 고치기 (사용자가 요청할 때만)
- 사용자가 고쳐 달라고 하면 지적 순서대로 고친다. 대상 레포 규칙과 토큰을 따르고 요청 범위를 넘지 않는다. 고친 뒤 같은 방법으로 다시 확인하고 전후를 보고한다.
- 해결 방법이 여러 개이고 취향이 갈리는 지적(내비게이션 형태, 알림 방식, 레이아웃)은 임의로 고르지 않는다. propose처럼 후보를 시안으로 그려 선택받을 수 있다고 안내한다.

## 하지 않는 것

- 요청 없이 파일을 고치지 않는다.
- 기본 규칙에 없는 개인 취향을 결함으로 지적하지 않는다. 근거가 없으면 지적하지 않는다.
- 렌더를 보지 못했는데 본 것처럼 쓰지 않는다.
