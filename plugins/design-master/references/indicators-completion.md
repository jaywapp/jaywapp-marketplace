# 인디케이터와 완료 표시 (인디케이터 9종, 완료 표시 9종)

"지금 어디에 있는지"와 "끝났다"를 알려 주는 요소다. 로딩 중 표시는 [empty-loading.md](empty-loading.md), 알림 형태는 [feedback.md](feedback.md), 모션 수치는 [motion.md](motion.md).

## A. 인디케이터 9종

### 프로그레스 바 (Progress bar)
- 참조: 본문은 [empty-loading.md](empty-loading.md)의 진행 바에 있다. 인디케이터 맥락에서는 여러 단계 중 한 구간의 진행(파일 업로드, 프로필 완성도)을 보여 줄 때 쓴다.

### 스텝 인디케이터 (Step indicator)
- 무엇: 여러 단계로 나뉜 흐름에서 전체 단계 수와 현재 위치, 지나온 단계를 보여 주는 표시(Stepper).
- 언제: 가입, 결제, 설문처럼 순서가 있는 3~6단계 흐름.
- 피할 때: 단계가 7개 이상이거나 사용자의 선택에 따라 단계가 바뀌는 흐름(진행 바나 `2/8` 텍스트가 낫다).
- 구현 주의: 완료, 현재, 예정을 모양과 색, 아이콘으로 구분한다(색만 쓰지 않는다). 현재 단계에 `aria-current="step"`. 모바일에서는 번호 `2 / 4`와 막대로 줄인다. 이미 지나온 단계로 돌아갈 수 있으면 눌림 가능하게 하되 방법을 보여 준다.
- 비슷한 것: 페이지 인디케이터(나란한 콘텐츠 중 위치, 순서가 필수는 아님), 진행 바(연속 값).

### 페이지 인디케이터 (Page indicator)
- 무엇: 가로로 넘기는 여러 화면(캐러셀, 온보딩 슬라이드)에서 현재 위치를 점으로 알리는 표시.
- 언제: 슬라이드 3~7장, 온보딩, 이미지 갤러리.
- 피할 때: 항목이 8개 이상(점이 너무 많아진다. `3 / 12`처럼 숫자로).
- 구현 주의: 점 지름 6~8px, 간격 8px, 활성 점은 색과 크기(길어진 알약)로 구분. 점이 너무 작아 누르기 어려우면 눌림 영역만 키우고 보이는 크기는 유지한다. 접근성을 위해 이전·다음 버튼도 둔다. 자동 넘김이 있으면 일시정지.
- 비슷한 것: 스텝 인디케이터, 스토리 바(시간 기반).

### 스토리 바 (Story progress)
- 무엇: 상단에 가로로 이어진 막대들이 시간에 따라 차례로 채워지며 스토리나 슬라이드의 길이를 보여 주는 표시.
- 언제: 자동으로 넘어가는 스토리형 콘텐츠, 짧은 하이라이트.
- 피할 때: 읽기에 시간이 필요한 콘텐츠를 자동으로 넘길 때(정지 수단이 필수).
- 구현 주의: 항목당 5~7초가 흔하다. 길게 눌러 일시정지, 좌우 탭으로 이동. 막대 높이 2~3px, 사이 간격 2~4px. 자동 전환은 접근성을 위해 정지할 수 있어야 한다.
- 비슷한 것: 페이지 인디케이터(수동 넘김).

### 스크롤 진행 바 (Scroll progress)
- 무엇: 화면 상단에 가는 막대로 긴 글을 얼마나 읽었는지 보여 주는 표시.
- 언제: 긴 글, 문서, 블로그.
- 피할 때: 짧은 페이지, 무한 스크롤(끝이 없다).
- 구현 주의: 높이 2~4px, 고정 헤더와 겹치지 않게 헤더 위나 아래에 붙인다. 계산은 스크롤 위치/(문서 높이 - 뷰포트 높이). 스크롤 이벤트마다 레이아웃을 읽지 않고 `animation-timeline: scroll()`이나 `requestAnimationFrame`으로 처리. 장식이므로 `aria-hidden`.
- 비슷한 것: 프로그레스 바(작업 진행).

### 원형 진행률 (Progress ring)
- 참조: 본문은 [empty-loading.md](empty-loading.md)의 진행 링에 있다. 인디케이터 맥락에서는 목표 달성률, 운동 링, 타이머 같은 지속 지표에 쓴다.

### 강도 표시기 (Strength meter)
- 참조: 본문은 [inputs.md](inputs.md)의 텍스트 필드 모션 중 Strength meter에 있다. 비밀번호 강도 말고 신호 세기, 난이도 같은 단계형 표시에도 같은 4단계 막대 방식을 쓸 수 있다.

### 탭 인디케이터 (Tab indicator)
- 무엇: 탭 목록에서 활성 탭 아래에 두는 막대나 하이라이트 표시.
- 언제: 상단 탭, 세그먼트, 하단 메뉴에서 현재 위치를 알릴 때.
- 구현 주의: 두께 2~3px, 탭 폭에 맞춰 길이 변화, 이동은 200~300ms ease-out. 색만 아니라 글자 굵기도 바꾼다. 탭 목록이 스크롤되면 활성 탭이 화면 안에 들어오게 스크롤한다. 하단 메뉴 스타일은 [navigation.md](navigation.md)의 Tab with indicator.
- 비슷한 것: 페이지 인디케이터(점), 스텝 인디케이터.

### 홈 인디케이터 (Home indicator)
- 무엇: iOS 화면 맨 아래에 있는 가는 막대로, 홈으로 가는 제스처 영역을 나타내는 시스템 요소.
- 언제: 직접 만드는 요소가 아니라 피해야 하는 영역이다. 하단 탭바, 하단 버튼, 바텀시트가 이 영역과 겹치지 않게 한다.
- 피할 때: 중요한 버튼을 화면 맨 아래 가장자리에 붙일 때(제스처와 충돌한다).
- 구현 주의: `padding-bottom: env(safe-area-inset-bottom)`을 쓰고 `viewport-fit=cover`를 지정해야 값이 들어온다. 안드로이드 제스처 바도 비슷하다. 탭 안쪽 위아래 패딩 16px 기준은 [spacing.md](spacing.md).
- 비슷한 것: 하단 탭바(이 영역을 비워야 하는 대표 요소).

## B. 완료 표시 9종

공통: 완료 연출은 짧게(300~1200ms, 컨페티 등 큰 연출은 최대 2초). 의미 전달은 글자나 아이콘이 맡고 모션은 보조한다. 자주 반복되는 행동에는 작게, 드문 큰 성취에만 크게 한다. `prefers-reduced-motion`이면 최종 상태만 즉시 보여 준다.

### 체크 그리기 (Check animation)
- 무엇: 원이나 체크 표시가 선을 따라 그려지며 완료를 알리는 모션.
- 언제: 저장, 결제, 인증 완료 같은 확실한 성공 순간.
- 구현 주의: SVG `stroke-dashoffset`으로 400~600ms. 원 그리기 다음 체크 순서. 마지막 상태가 정지 이미지로도 의미가 통해야 한다. 옆에 글(`완료됐어요`)을 둔다.
- 비슷한 것: 완료 화면(체크가 화면 전체를 대표하는 경우).

### 할 일 줄긋기 (Strikethrough)
- 무엇: 체크하면 해당 항목에 취소선이 그어지고 약간 흐려지는 완료 표현.
- 언제: 체크리스트, 할 일 목록.
- 피할 때: 완료된 항목이 중요하게 읽혀야 하는 화면(청구서 내역).
- 구현 주의: 선이 왼쪽에서 오른쪽으로 그려지는 200~300ms. 흐려도 읽을 수 있는 대비를 유지(4.5:1 미만이 되면 접근성 위험). 체크박스 상태와 `aria-checked`가 일치. 완료 항목을 아래로 보낼지 그대로 둘지 정한다.
- 비슷한 것: 체크 그리기(체크박스 안의 모션).

### 버튼 모핑 (Button morph)
- 무엇: 버튼이 누른 뒤 로딩, 체크 표시로 모양이 변하며 완료를 알리는 연출.
- 언제: 제출, 저장, 구독처럼 버튼 하나에서 흐름이 끝나는 행동.
- 구현 주의: 폭이 줄었다 다시 복귀하므로 주변 레이아웃을 흔들지 않게 컨테이너 폭을 고정한다. 단계(기본, 로딩, 성공)를 [inputs.md](inputs.md)의 버튼 상태와 맞춘다. 1~2초 후 기본으로 복귀하거나 다음 행동 버튼으로 전환.
- 비슷한 것: 성공(버튼 상태 하나).

### 진행률 완료 (Progress complete)
- 무엇: 진행 바나 링이 100%에 도달할 때 색이 바뀌고 체크로 전환되는 표시.
- 언제: 업로드, 설치, 프로필 완성도의 끝.
- 구현 주의: 100%에서 잠깐 머문 뒤 완료 상태로 전환. 100%인데 실제 처리가 안 끝난 상태를 만들지 않는다(마지막 몇 퍼센트는 실제 완료 후에). 완료 문구 `업로드 완료`를 함께.
- 비슷한 것: 진행 바와 진행 링([empty-loading.md](empty-loading.md)).

### 보냄 애니메이션 (Send animation)
- 무엇: 메시지나 폼이 전송되었음을 종이비행기가 날아가거나 입력이 위로 사라지는 연출로 알리는 모션.
- 언제: 메시지 전송, 문의 제출.
- 구현 주의: 400~700ms. 실제 전송 상태(전송 중, 전송됨, 실패)와 연동한다. 날아간 뒤 실패하면 되돌려 재시도를 보여 준다. 낙관적 UI와 같이 쓸 때 실패 처리 필수([empty-loading.md](empty-loading.md)).
- 비슷한 것: 버튼 모핑.

### 스탬프 (Stamp)
- 무엇: 도장이 찍히듯 확대에서 축소로 내려앉으며 완료나 승인을 알리는 연출.
- 언제: 출석, 승인, 인증 완료처럼 기록된다는 느낌이 중요한 순간.
- 구현 주의: 300~500ms, 크게 시작해서 1.0으로 안착하며 약간의 바운스. 도장 글자는 번역 가능한 텍스트로 만든다(이미지 속 글자 금지). 사라지지 않고 상태로 남는다.
- 비슷한 것: 배지 획득(수집 요소).

### 배지 획득 (Badge unlock)
- 무엇: 업적이나 보상을 얻었을 때 배지가 해금되며 나타나는 연출.
- 언제: 학습, 게임화 요소, 첫 번째 달성.
- 피할 때: 사소한 행동마다 터뜨릴 때(가치가 떨어진다).
- 구현 주의: 획득 이유를 글로 알린다(`7일 연속 달성`). 닫기 쉬운 오버레이로 열고, 나중에 다시 볼 수 있는 보관 화면을 둔다. 600~1000ms, 빛이나 회전은 `prefers-reduced-motion` 때 정적 표시.
- 비슷한 것: 뱃지(알림 수 표시, [feedback.md](feedback.md)와 다른 요소).

### 컨페티 (Confetti)
- 무엇: 색종이가 화면에 터지는 축하 연출.
- 언제: 드문 큰 성취(첫 결제 완료, 목표 달성, 출시 이벤트).
- 피할 때: 반복 행동, 업무·금융처럼 신중한 맥락, 오류가 가능한 흐름(실제 완료 확인 전).
- 구현 주의: 1.5~2초 안에 끝나게 하고 입자 수를 제한해 성능을 지킨다. 화면 조작을 막지 않는다(`pointer-events: none`). `prefers-reduced-motion`이면 생략. 의미는 글로 전달.
- 비슷한 것: 완료 화면(축하와 다음 행동을 담는다).

### 완료 화면 (Success screen)
- 무엇: 흐름이 끝났음을 전체 화면으로 알리고 다음 행동을 안내하는 화면.
- 언제: 주문, 가입, 신청처럼 여러 단계 흐름의 끝.
- 피할 때: 작은 저장 같은 가벼운 행동(토스트나 버튼 성공 상태로 충분하다).
- 구현 주의: 체크 아이콘, 한 줄 결과(`주문이 접수됐어요`), 핵심 정보(번호, 날짜), 주 행동 하나(`주문 내역 보기`)와 보조 하나(`홈으로`). 뒤로 가면 제출 화면이 다시 뜨지 않게 이력을 정리한다. 확인 메일 같은 후속 정보를 알린다.
- 비슷한 것: 체크 그리기(화면 중앙 아이콘), 모두 완료([empty-loading.md](empty-loading.md), 빈 목록의 완료).
