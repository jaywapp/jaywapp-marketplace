# 기본 품질 규칙

화면을 만들거나 점검할 때 항상 적용하는 규칙이다. 각 규칙에는 직접 확인하는 방법이 있다. 대상 레포에 디자인 시스템이 있으면 그 값이 우선이고, 여기 수치는 그것이 없을 때의 기본값이다. review 스킬은 이 문서의 모든 규칙(Q01~Q16)을 번호로 인용한다.

## Q01. 텍스트 대비
- 규칙: 본문 글자와 배경의 대비는 4.5:1 이상, 큰 글자(24px 이상, 또는 굵은 글씨 약 19px 이상)는 3:1 이상. 아이콘과 입력 칸 테두리 같은 UI 요소는 3:1 이상. 사진이나 그라디언트 위의 글자는 가장 밝은(어두운) 지점 기준.
- 확인 방법: 전경색과 배경색 값을 대비 계산식으로 계산하거나 브라우저 개발자 도구의 대비 표시를 본다. 비활성 상태, 플레이스홀더, 호버 상태도 확인. 흔한 위반은 연한 회색 보조 글자(#999 on 흰색은 약 2.8:1).

## Q02. 터치 타깃
- 규칙: 누를 수 있는 요소의 크기는 권장 44x44px(안드로이드 권장 48x48dp). 참고로 WCAG 2.2 AA의 최소 기준(2.5.8)은 24x24px이다. 심각도는 24px 미만이면 높음, 24~43px이면 중간으로 본다(review와 같은 기준). 인접한 타깃 사이 간격은 8px 이상, 버튼 사이는 12px. 아이콘이 작아도 눌림 영역은 키운다.
- 확인 방법: 개발자 도구에서 요소 크기를 재거나 모바일 폭에서 엄지로 눌러 본다. 아이콘 버튼은 `padding`을 포함한 크기를 본다. 이동 막대와 목록 항목 높이도 같다.

## Q03. 간격 체계 일관성
- 규칙: 간격은 [spacing.md](spacing.md)의 토큰 값만 쓰고(값 목록은 거기가 유일한 출처) 같은 관계에는 같은 값을 쓴다. 테두리나 면으로 묶이지 않은 묶음은 안쪽 간격이 묶음 사이 간격보다 작다. 데스크톱의 큰 섹션 간격(48~96px 등)은 토큰 체계 안에서 허용된다.
- 확인 방법: 코드에서 임의의 px 값(13, 18, 27 등)을 검색. 화면에서 같은 종류 요소(카드, 섹션)의 간격이 같은지 눈으로 비교. 간격 토큰 밖의 값은 위반.

## Q04. 글자 크기 단계와 줄 길이
- 규칙: 글자 크기 단계는 5~6개 이내(예: 12, 14, 16, 20, 24, 32). 본문은 모바일 16px 이상(입력 칸 글자도 16px 이상). 줄 높이는 본문 1.4~1.6. 한 줄 길이는 라틴 문자 기준 45~75자(약 `65ch`), 한글 기준으로는 대략 한 줄 30~40자. 한 화면에 굵기도 2~3종까지.
- 확인 방법: 화면에서 쓰인 글자 크기를 모두 모아 개수를 센다. 데스크톱 넓은 폭에서 본문 줄이 너무 길어지지 않는지(`max-width: 65ch`)와 모바일에서 글자가 12px 아래로 내려가지 않는지 본다.

## Q05. 색 사용
- 규칙: 강조색은 하나(주 행동과 현재 위치에만). 의미색(오류 붉은색, 성공 초록, 경고 노랑, 정보 파랑)은 강조색과 별도로 의미에만 쓴다. 색만으로 의미를 전달하지 않고 아이콘이나 글자를 함께 쓴다. 색 개수는 중립색 + 강조색 1 + 의미색 4 이내.
- 확인 방법: 화면을 흑백으로 바꿔도(개발자 도구의 색각 시뮬레이션) 상태 구분이 되는지 본다. 같은 색이 서로 다른 의미로 쓰이는지, 한 화면에 강조색이 여러 색인지 확인.

## Q06. 모서리 반경 일관성
- 규칙: 모서리 반경은 2~3단계로 정한다(예: 작은 요소 8px, 카드 16px, 알약 9999px). 안쪽 요소의 반경은 바깥 요소 반경에서 패딩을 뺀 값에 맞춘다(중첩 시).
- 확인 방법: 버튼, 입력 칸, 카드, 모달의 `border-radius`를 비교. 같은 종류가 다른 값이면 위반. 카드 안 이미지의 모서리와 카드 모서리가 어긋나지 않는지 본다.

## Q07. 그림자 일관성
- 규칙: 그림자는 높이 단계(예: 없음, 약함, 중간, 강함) 3~4개 정의로 쓰고 위계가 같은 요소는 같은 그림자를 쓴다. 광원 방향을 하나로(위에서 아래). 평평한 스타일이면 그림자 대신 윤곽선이나 면색으로 구분.
- 확인 방법: 모든 `box-shadow` 값을 검색해 종류를 센다. 카드와 모달, 드롭다운의 그림자 단계가 올바른 높이 순서(뜬 요소일수록 강함)인지 확인.

## Q08. 상태 누락
- 규칙: 상호작용 요소는 기본, hover, pressed, focus, disabled를 갖는다. 데이터가 있는 영역은 loading, error, empty(빈 화면)를 갖는다. 입력 칸은 입력됨, 오류, 읽기 전용도 갖는다. 설계에서 정한 상태가 구현에 모두 있어야 한다.
- 확인 방법: 키보드 Tab으로 포커스 링이 보이는지 확인. 개발자 도구로 hover와 active, disabled를 강제로 켠다. 네트워크 제한과 오프라인, 빈 데이터, 오류 응답을 만들어 화면을 본다. 상태 목록은 [inputs.md](inputs.md), [empty-loading.md](empty-loading.md).

## Q09. 라벨과 플레이스홀더
- 규칙: 입력 칸에는 항상 보이는 라벨이 있다. 플레이스홀더는 형식 예시에만 쓰고 라벨을 대신하지 않는다. 필수와 선택을 표시. 아이콘만 있는 버튼에는 접근 가능한 이름(`aria-label`)이 있다. 오류 문구는 원인과 해결 방법을 알려 준다.
- 확인 방법: 입력 칸에 값을 넣은 상태의 화면을 본다(라벨이 사라지면 위반). 개발자 도구의 접근성 트리에서 이름이 비어 있는 컨트롤을 찾는다. 구분은 [confusable-pairs.md](confusable-pairs.md).

## Q10. 정렬과 그룹화(근접성)
- 규칙: 관련 있는 요소는 가깝게, 관련 없는 요소는 멀리 둔다. 같은 열의 요소는 왼쪽 선을 맞춘다. 한 화면의 정렬선은 가능한 한 적게(왼쪽 정렬선 하나 + 오른쪽 하나). 텍스트는 왼쪽 정렬이 기본이고 가운데 정렬은 짧은 문구에만 쓴다.
- 확인 방법: 화면을 흐릿하게(눈을 가늘게 뜨고) 봤을 때 덩어리가 의도한 묶음과 같은지 본다. 개발자 도구의 요소 윤곽선으로 정렬선이 어긋난 요소를 찾는다. 간격 위계는 [spacing.md](spacing.md).

## Q11. 한 화면의 주 행동 하나
- 규칙: 한 화면(또는 한 시야)에 가장 눈에 띄는 버튼은 하나. 채움 버튼은 주 행동에만, 보조 행동은 윤곽선이나 글자 버튼. 파괴적 행동은 주 버튼과 떨어뜨리거나 확인을 거친다.
- 확인 방법: 화면을 보고 "여기서 사용자가 가장 먼저 해야 할 일"이 3초 안에 한 가지로 답해지는지 확인. 같은 강도의 채움 버튼이 두 개 이상이면 위반.

## Q12. 아이콘 일관성
- 규칙: 아이콘 세트는 하나(선 굵기, 모서리 처리, 채움 방식 통일). 크기는 16, 20, 24px 같은 단계. 의미가 불분명한 아이콘에는 글자 라벨을 붙인다. 이모지를 아이콘 대신 쓰지 않는다(플랫폼마다 모양이 다르다).
- 확인 방법: 화면의 아이콘을 모아 선 굵기와 스타일이 같은지 비교. 아이콘만 있는 버튼을 찾아 라벨이나 `aria-label`이 있는지 확인.

## Q13. 반응형
- 규칙: 360px(작은 폰), 390px(일반 폰), 768px(태블릿), 1280px(데스크톱) 폭에서 가로 스크롤이 생기지 않고 요소가 잘리거나 겹치지 않는다. 열 수는 폭에 따라 줄고, 내비게이션과 레이아웃은 폭에 맞는 형태로 바뀐다. 모바일 하단 고정 요소는 안전 영역을 고려한다.
- 확인 방법: 개발자 도구에서 위 폭으로 바꿔 보고 `document.documentElement.scrollWidth > innerWidth` 여부와 눈으로 확인. 글자 크기를 200%로 키워도 깨지지 않는지 확인.

## Q14. 다크 모드
- 규칙: 지원한다면 배경은 순수 검정(#000) 대신 어두운 회색, 글자는 순백 대신 약간 어두운 흰색을 쓰고 Q01 대비를 다시 충족한다. 그림자는 다크 모드에서 거의 보이지 않으므로 면 밝기 차이로 높이를 표현한다. 이미지와 일러스트, 아이콘의 색 반전이나 대체를 확인한다. 색은 토큰으로 정의해 한 곳에서 바꾼다.
- 확인 방법: `prefers-color-scheme: dark`로 전환해 모든 화면을 본다. 하드코딩된 색(#fff, #000)이 남아 있는지 검색. 지원하지 않는다면 명시적으로 라이트 고정(`color-scheme: light`).

## Q15. 실제 길이의 콘텐츠
- 규칙: 더미 글(lorem ipsum)이 아니라 실제와 비슷한 길이로 확인한다. 매우 긴 이름, 긴 제목(2줄 이상), 짧은 값, 0건, 1건, 100건 이상, 긴 번역 문구(영어보다 독일어는 30~40% 길다)에서 레이아웃이 유지된다. 긴 글은 줄임(`line-clamp`)이나 줄바꿈 처리가 되어 있다. 이미지는 비율을 고정하고 로딩 전 자리를 확보.
- 확인 방법: 가장 긴 사용자 이름과 제목을 직접 넣어 본다. 목록은 0, 1, 많은 수로 확인. 이미지 없음과 로딩 실패도 확인한다.

## Q16. 포커스와 키보드
- 규칙: 모든 상호작용 요소를 키보드로 도달하고 조작할 수 있다. 포커스 링은 항상 보이고 배경과 3:1 이상. 탭 순서는 화면 순서와 같다. 모달이 열리면 포커스가 안으로 들어가고 닫히면 돌아온다. 모션은 `prefers-reduced-motion`을 존중한다.
- 확인 방법: 마우스 없이 Tab, Shift+Tab, Enter, Space, Esc만으로 주요 흐름을 끝까지 해 본다. 포커스가 사라지는 지점이나 갇히는 지점을 찾는다. `outline: none`이 대체 스타일 없이 쓰였는지 검색.

## 빠른 점검 순서

1. 흑백으로 보아도 위계가 보이는가 (Q05, Q10, Q11)
2. 간격과 반경, 그림자가 몇 종류인가 (Q03, Q06, Q07)
3. 가장 작은 글자와 대비가 낮은 글자 (Q01, Q04)
4. 가장 작은 눌림 요소 (Q02)
5. 빠진 상태: 오류, 빈 화면, 로딩, 비활성 (Q08)
6. 좁은 폭과 긴 콘텐츠 (Q13, Q15)
7. 키보드와 다크 모드 (Q16, Q14)
