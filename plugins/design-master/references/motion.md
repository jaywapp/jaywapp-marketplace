# 모션 (움직임 이름 9종, 화면 전환 9종, 텍스트 등장 9종)

## 공통 기준

| 용도 | 지속 시간 | 이징 |
|---|---|---|
| 버튼·토글 같은 작은 반응 | 100~200ms | ease-out |
| 툴팁, 드롭다운, 작은 요소 등장 | 150~250ms | ease-out |
| 모달, 시트, 화면 일부 전환 | 250~350ms | 등장은 ease-out, 퇴장은 ease-in |
| 전체 화면 전환 | 300~400ms | ease-in-out 또는 약한 스프링 |
| 큰 연출(온보딩, 축하) | 500ms~1.5초 | 의도에 따라 |

- 퇴장은 등장보다 20~30% 짧게. 사용자의 입력에 대한 반응은 100ms 안에 시작한다.
- 한 번에 움직이는 요소를 줄이고 한 화면에서는 같은 이징을 쓴다.
- `prefers-reduced-motion: reduce`에서는 이동, 확대, 회전, 시차 같은 큰 움직임을 끄거나 페이드로 바꾼다. 의미를 모션에만 담지 않는다.
- 성능: `transform`과 `opacity`만 애니메이션하고 `width`, `height`, `top`, `left`는 피한다. 알약처럼 크기가 바뀌어야 하는 요소는 `transform: translateX`와 `scaleX`로 하거나, 작은 요소 하나에 한해 폭 변화를 예외로 허용한다(레이아웃에 영향이 없는 절대 위치 요소일 때).

## A. 움직임 이름 9종

### 이즈 인 (Ease-in)
- 무엇: 처음에는 느리고 끝으로 갈수록 빨라지는 속도 곡선.
- 언제: 화면 밖으로 나가는 요소(퇴장). 가속하며 사라지는 느낌.
- 피할 때: 등장하는 요소와 사용자 입력에 반응하는 요소. 시작이 느려서 굼뜨게 느껴진다.
- 구현 주의: `cubic-bezier(0.4, 0, 1, 1)` 또는 `ease-in`. 퇴장 150~250ms.
- 비슷한 것: 이즈 아웃(반대).

### 이즈 아웃 (Ease-out)
- 무엇: 처음에 빠르게 시작해 끝에서 느려지며 멈추는 속도 곡선.
- 언제: 등장하는 요소, 사용자 입력에 대한 반응. 대부분의 UI 기본값.
- 피할 때: 끝에서 멈추는 것이 어색한 연속 회전(선형이 맞다).
- 구현 주의: `cubic-bezier(0, 0, 0.2, 1)` 또는 `ease-out`. 200~300ms.
- 비슷한 것: 이즈 인(반대), 스프링(끝에서 넘쳤다 돌아온다).

### 스프링 (Spring)
- 무엇: 목표 위치를 살짝 넘어갔다가 되돌아와 멈추는, 물리 기반의 곡선.
- 언제: 드래그 후 놓았을 때, 시트나 카드가 제자리를 찾을 때, 살아 있는 느낌이 필요한 인터랙션.
- 피할 때: 업무용 화면의 잦은 전환, 접근성이 중요한 곳(많이 넘치는 설정).
- 구현 주의: 강성(stiffness)과 감쇠(damping)로 정의하며 넘침을 약하게(감쇠비 약 0.7~0.9). 전체 시간 300~500ms. CSS는 `linear()` 함수로 근사하거나 라이브러리(Framer Motion, React Spring 등)를 쓴다.
- 비슷한 것: 바운스(여러 번 튄다).

### 바운스 (Bounce)
- 무엇: 바닥에 떨어진 공처럼 여러 번 튀며 멈추는 움직임.
- 언제: 알림 주목, 장난스러운 브랜드, 어린이·게임 앱, 짧은 보상 연출.
- 피할 때: 반복되거나 업무·금융 화면. 눈에 띄는 만큼 피로가 크다.
- 구현 주의: 튀는 횟수 2~3회, 총 600ms 이내. 반복 재생(무한)은 피하고 한 번만 재생. `prefers-reduced-motion`이면 생략.
- 비슷한 것: 스프링(한두 번 넘치고 멈춘다).

### 순차 등장 (Stagger)
- 무엇: 여러 요소를 한꺼번에 나타내지 않고 짧은 간격을 두고 하나씩 차례로 나타내는 연출.
- 언제: 목록, 카드 모음, 메뉴 항목이 처음 나타날 때.
- 피할 때: 항목이 많아(10개 이상) 마지막 항목까지 오래 걸릴 때. 반복 방문 화면.
- 구현 주의: 항목 간 지연 30~80ms, 전체 지연 합 500ms 이하(항목이 많으면 첫 몇 개만). 각 항목의 이동은 8~16px와 페이드. `animation-delay`를 `calc(var(--i) * 50ms)`처럼 인덱스로 준다.
- 비슷한 것: 페이드(전체가 동시), 글자 순차 등장(글자 단위).

### 페이드 (Fade)
- 무엇: 투명도를 0에서 1로(또는 반대로) 바꾸는 가장 기본적인 전환.
- 언제: 요소의 등장·퇴장, 관계가 약한 화면의 교체, 접근성 대체 모션(다른 모션을 줄일 때).
- 피할 때: 공간적 관계(어디서 왔는지)를 알려야 할 때(슬라이드나 공유 요소).
- 구현 주의: 150~300ms. 페이드로 사라진 요소는 `visibility: hidden`이나 `inert`로 포커스와 읽기 대상에서도 제거한다.
- 비슷한 것: 페이드 스루(두 화면이 겹치지 않고 순차로).

### 슬라이드 (Slide)
- 무엇: 요소가 한 방향에서 미끄러져 들어오거나 나가는 이동.
- 언제: 계층 이동(오른쪽에서 들어오는 상세), 시트나 드로어, 목록 항목 삭제.
- 피할 때: 방향 의미가 없는 곳. 방향은 정보다: 앞으로 갈 때는 새 화면이 오른쪽에서 들어오고, 뒤로 갈 때는 현재 화면이 오른쪽으로 나가고 이전 화면이 왼쪽에서 들어온다.
- 구현 주의: `transform: translateX/Y`. 등장은 이즈 아웃 250~350ms. 이동 거리가 짧으면 페이드와 합친다. 읽는 방향이 반대인 언어에서는 방향을 뒤집는다.
- 비슷한 것: 푸시(전체 화면 단위).

### 확대 전환 (Zoom transition)
- 무엇: 작은 요소가 커지며 화면을 채우거나 전체 화면이 축소되며 요소가 되는 확대·축소 전환.
- 언제: 썸네일에서 상세로, 이미지 확대 보기.
- 구현 주의: 이 항목은 움직임의 종류이고, 화면 단위의 전환은 [화면 전환의 줌](#줌-zoom)에 있다. `transform: scale`을 쓰고 0에서 시작하지 말고 0.9~0.95에서 시작해 페이드와 함께. 250~350ms.
- 비슷한 것: 공유 요소 전환(연결된 요소가 이동한다).

### 공유 요소 전환 (Shared element)
- 무엇: 두 화면에 모두 있는 같은 요소(예: 썸네일과 상세 이미지)가 화면이 바뀌는 동안 끊김 없이 이동하며 변형되는 전환.
- 언제: 목록의 카드를 눌러 상세로 갈 때, 사진을 열 때. 어디서 왔는지 맥락을 유지하고 싶을 때.
- 피할 때: 두 화면 사이에 대응되는 요소가 없을 때, 목록 항목이 많아 성능이 떨어질 때.
- 구현 주의: 웹은 View Transitions API(`view-transition-name`)로 구현하고 지원 여부를 확인해 대체(페이드)를 준비한다. 뒤로 가기에서도 역방향으로 같은 요소가 돌아가야 한다. 300~400ms. 모바일은 플랫폼의 Hero(Flutter)나 Shared Element Transition(Android) 사용.
- 비슷한 것: 카드 확장(요소가 화면 전체로 커진다).

## B. 화면 전환 9종

### 푸시 (Push)
- 무엇: 새 화면이 옆에서 밀고 들어오며 이전 화면이 약간 밀려나는 계층 이동 전환.
- 언제: 목록에서 상세로, 설정에서 하위 설정으로.
- 구현 주의: 새 화면은 오른쪽에서 들어오고 이전 화면은 왼쪽으로 30% 정도 밀린다. 300~350ms. 뒤로 가기는 반대 방향이며 가장자리 스와이프로 조작 가능하게. [navigation.md](navigation.md)의 뒤로 가기.
- 비슷한 것: 모달 등장(계층이 아닌 위에 얹기).

### 모달 등장 (Modal present)
- 무엇: 새 화면이나 패널이 아래에서 올라와 현재 화면 위에 얹히는 전환.
- 언제: 새로 만들기, 독립 작업(작성, 설정), 흐름이 끝나면 돌아올 곳이 명확한 작업.
- 구현 주의: 아래에서 위로 이동 300~350ms. 뒤 화면은 살짝 어둡게. 닫을 때 반대로. 닫기 버튼과 아래로 쓸기 모두 제공.
- 비슷한 것: 시트 확장, 푸시.

### 페이드 스루 (Fade through)
- 무엇: 이전 화면이 먼저 사라진 뒤 새 화면이 나타나는, 두 화면이 겹치지 않는 전환.
- 언제: 하단 탭 사이 전환처럼 서로 관계가 약한 동등한 화면 사이.
- 구현 주의: 퇴장 90ms 페이드 아웃 후 입장 210ms 페이드 인(+ 새 화면은 살짝 확대 0.92→1). 총 300ms 안팎.
- 비슷한 것: 탭 전환(같은 개념의 구체 사례), 페이드(단순).

### 공유 요소 (Shared element)
- 참조: 본문은 이 문서 A절의 [공유 요소 전환](#공유-요소-전환-shared-element)에 있다.

### 카드 확장 (Card expand)
- 무엇: 카드가 그 자리에서 커져 화면 전체를 채우는 상세 화면이 되는 전환.
- 언제: 카드형 목록에서 항목을 열 때, 지도 위 카드에서 상세로.
- 구현 주의: 카드의 위치와 크기에서 화면 크기로 컨테이너가 변형된다. 내용은 늦게 페이드로 나타난다. 닫을 때 같은 카드 위치로 돌아간다. 스크롤 위치 보존. 350~400ms.
- 비슷한 것: 공유 요소 전환(핵심 요소만 이동), 시트 확장.

### 줌 (Zoom)
- 무엇: 화면이 확대되며 들어가거나 축소되며 나오는 전환.
- 언제: 갤러리의 사진 열기, 폴더 열기, 계층 깊이를 표현할 때.
- 구현 주의: scale 0.9~1.1 범위와 페이드 병행. 큰 배율(3배 이상)은 멀미를 줄 수 있으므로 줄인다. 확대의 기본 개념은 [확대 전환](#확대-전환-zoom-transition).
- 비슷한 것: 카드 확장(출발 요소가 있다).

### 순차 등장 (Stagger in)
- 참조: 본문은 A절의 [순차 등장](#순차-등장-stagger)에 있다. 화면 전환 때는 새 화면의 주요 요소 3~5개를 순차로 보여 준다.

### 탭 전환 (Tab switch)
- 무엇: 탭을 바꿀 때 내용이 교체되는 전환.
- 언제: 상단 탭과 하단 탭의 내용 전환.
- 구현 주의: 하단 탭은 보통 즉시 교체나 페이드 스루. 상단 탭은 좌우로 넘기는 슬라이드가 자연스럽다(탭 순서 방향과 일치). 각 탭의 스크롤 위치와 입력 상태를 보존한다. 200~300ms.
- 비슷한 것: 페이드 스루.

### 시트 확장 (Sheet expand)
- 무엇: 바텀시트가 올라와 절반에서 전체 높이로 확장되는 전환.
- 언제: 지도 위 상세, 음악 플레이어 미니에서 전체로, 공유나 선택 시트.
- 구현 주의: 끌기에 따라 연속적으로 따라온다(제스처 연동). 놓을 때 가까운 단계로 스프링 스냅. 확장되면서 안의 레이아웃이 바뀌면 크로스페이드. 시트 자체는 [feedback.md](feedback.md)의 바텀시트.
- 비슷한 것: 모달 등장, 카드 확장.

## C. 텍스트 등장 9종

공통: 글을 읽기 전에 사라지거나 읽는 속도를 늦추면 안 된다. 중요한 정보에는 쓰지 않는다. 같은 화면에서 한 가지만. 스크린 리더에는 완성된 텍스트를 처음부터 제공한다. `span`, `div`, `p` 같은 generic 요소에는 `aria-label`이 읽히지 않을 수 있으므로, 원문을 시각적으로 숨긴 텍스트(`.sr-only`: `position:absolute; width:1px; height:1px; overflow:hidden; clip-path:inset(50%); white-space:nowrap`)로 한 번 넣고 효과용 `span`에는 `aria-hidden="true"`를 둔다. `aria-label`은 버튼, 링크, 이미지, `role="img"`처럼 이름을 붙일 수 있는 역할에만 쓴다. `prefers-reduced-motion`이면 즉시 표시한다.

### 타이핑 (Typewriter)
- 무엇: 글자가 한 글자씩 입력되는 것처럼 나타나는 효과.
- 언제: 짧은 히어로 문구, 터미널 느낌, AI 답변 흉내.
- 피할 때: 긴 문장, 사용자가 읽어야 할 안내. 실제 스트리밍 데이터는 [empty-loading.md](empty-loading.md)의 스트리밍 텍스트.
- 구현 주의: 글자당 30~60ms. 전체 2~3초 이내. 레이아웃이 줄바꿈으로 흔들리지 않게 최종 텍스트 크기를 미리 확보. 커서 깜빡임은 선택.

### 페이드 업 (Fade up)
- 무엇: 글이 아래에서 8~24px 위로 올라오며 서서히 나타나는 효과.
- 언제: 스크롤 시 섹션 제목, 문단의 등장. 가장 무난한 선택.
- 구현 주의: 400~600ms, ease-out, 이동 거리 짧게. 뷰포트에 들어올 때 한 번만(IntersectionObserver). 이미 본 위치로 스크롤을 되돌려도 반복하지 않는다.

### 글자 순차 등장 (Letter stagger)
- 무엇: 글자(또는 단어)마다 시간차를 두고 나타나는 효과.
- 언제: 큰 제목 한 줄, 브랜드 이름.
- 피할 때: 본문, 긴 제목. 한글은 자모 결합이 있으므로 글자(음절) 단위로 나눈다.
- 구현 주의: 글자 간 지연 20~50ms, 전체 1초 이내. 글자를 `span`으로 나눌 때 원문은 `.sr-only` 텍스트로 한 번 넣고 나뉜 span들은 `aria-hidden="true"`로 둔다.

### 카운트 업 (Count up)
- 무엇: 숫자가 0에서 목표값까지 올라가며 보이는 효과.
- 언제: 지표 소개, 통계, 점수 결과. 큰 수치를 강조할 때.
- 피할 때: 정확한 값을 빨리 읽어야 하는 업무 화면, 값이 자주 바뀌는 실시간 지표.
- 구현 주의: 1~2초, 끝에서 느려지는 이즈 아웃. 숫자 폭이 변해 레이아웃이 흔들리지 않게 `font-variant-numeric: tabular-nums`. 최종 값은 `.sr-only` 텍스트로 제공하고 올라가는 숫자는 `aria-hidden="true"`. 뷰포트 진입 시 한 번만.

### 스크램블 (Scramble)
- 무엇: 무작위 글자가 섞여 바뀌다가 최종 글자로 정리되는 효과.
- 언제: 기술적·사이버 느낌의 브랜드, 해독하는 연출.
- 피할 때: 대부분의 일반 서비스. 읽기 어렵고 한글은 효과가 어색하다.
- 구현 주의: 0.6~1.2초. 최종 텍스트로 확정되기 전에 읽히지 않으므로 중요 정보에는 쓰지 않는다. 고정폭 글꼴이면 폭이 흔들리지 않는다.

### 마스크 리빌 (Mask reveal)
- 무엇: 글자가 가려진 영역(마스크) 뒤에서 위로 올라오거나 펼쳐지며 드러나는 효과.
- 언제: 편집 느낌의 제목, 브랜드 소개.
- 구현 주의: 줄마다 `overflow: hidden`인 래퍼를 두고 안의 텍스트를 `translateY(100%)`에서 0으로. 줄 단위로 40~80ms 간격. 600~800ms. 줄바꿈이 반응형으로 바뀌므로 줄 분할을 너비 변화에 맞춰 다시 계산한다.

### 하이라이트 (Highlight)
- 무엇: 글 일부에 형광펜 같은 배경이 그려지며 강조되는 효과.
- 언제: 핵심 단어를 한 번 짚어 줄 때.
- 구현 주의: 배경 크기를 0%에서 100%로(`background-size`), 500~800ms. 강조 색과 글자 색의 대비 4.5:1 유지. 한 화면에서 1~2곳만. 효과가 끝난 상태로도 의미가 보존되게.

### 단어 교체 (Word rotate)
- 무엇: 문장 안의 한 단어가 일정 시간마다 다른 단어로 바뀌는 효과.
- 언제: 제품이 쓰이는 여러 상황을 짧게 보여 줄 때(`___를 위한 도구`).
- 피할 때: 중요한 정보를 단어 하나에 담을 때(놓친다), 긴 단어들(폭 변화).
- 구현 주의: 단어당 2~3초 노출, 전환 300ms. 가장 긴 단어로 폭을 고정. `aria-live`를 쓰지 않고 정적 문장 또는 첫 단어만 읽히게. 일시정지 수단(호버나 포커스 시 정지). 5개 이내.

### 블러 인 (Blur in)
- 무엇: 흐릿하고 투명한 글이 선명해지며 나타나는 효과.
- 언제: 부드럽고 몽환적인 분위기의 제목, 히어로 문구.
- 구현 주의: `filter: blur(8px → 0)`과 opacity, 500~800ms. 블러는 성능 비용이 크므로 큰 영역과 반복 사용을 피한다. 읽기 대상이 되는 글에는 쓰지 않는다.
