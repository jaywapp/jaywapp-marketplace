# 내비게이션 (화면 이동 9종, 모바일 하단 메뉴 스타일 11종, 탭 바 전환 모션 6종)

사용자가 화면 사이를 옮겨 다니는 방법이다. 화면 전환 애니메이션은 [motion.md](motion.md), 간격 수치는 [spacing.md](spacing.md).

## A. 화면 이동 9종

### 하단 탭바 (Tab bar)
- 무엇: 모바일 화면 아래에 앱의 최상위 목적지를 아이콘과 라벨로 늘어놓은 막대.
- 언제: 서로 대등하고 자주 오가는 주요 화면이 3~5개일 때.
- 피할 때: 목적지가 6개 이상이거나 사용 빈도 차가 클 때(더보기 탭이나 드로어로 분리). 순서가 있는 흐름(스테퍼).
- 구현 주의: 항목 4~5개, 터치 영역 최소 48x48px, 아이콘과 라벨을 함께 쓴다. 활성 상태는 색 하나에 의존하지 않고 채움이나 굵기, 표시 막대를 더한다. 하단 안전 영역(`env(safe-area-inset-bottom)`)을 비운다. 탭을 다시 누르면 맨 위로 스크롤하는 관례가 있다.
- 비슷한 것: 상단 탭(같은 화면 안의 보기 전환), 앱 바 vs 탭 바([confusable-pairs.md](confusable-pairs.md)).

### 상단 탭 (Top tabs)
- 무엇: 한 화면 안에서 같은 종류의 콘텐츠를 보기별로 나누는 가로 탭.
- 언제: 한 주제의 하위 보기(전체, 진행 중, 완료)를 빠르게 바꿀 때.
- 피할 때: 앱 전체 이동(하단 탭바), 탭 항목이 7개를 넘을 때(스크롤 탭은 숨은 항목을 놓친다), 상호 배타적 설정값 선택(세그먼트).
- 구현 주의: 라벨은 짧게 1~2단어. 활성 탭 아래 2~3px 밑줄과 글자 굵기 변화를 같이 쓴다. 가로 스크롤 탭은 잘린 다음 항목이 보이게 한다. ARIA는 `role="tablist"`, `tab`, `tabpanel`과 좌우 화살표 키.
- 비슷한 것: 탭 vs 세그먼트([confusable-pairs.md](confusable-pairs.md)).

### 드로어 (Navigation drawer)
- 무엇: 화면 가장자리(주로 왼쪽)에서 밀려 나오는 메뉴 패널.
- 언제: 메뉴 항목이 많고 대부분 자주 쓰지 않을 때, 계정과 설정을 모아 둘 때, 태블릿·데스크톱 사이드바의 모바일 대응.
- 피할 때: 핵심 목적지를 숨기고 싶지 않을 때(하단 탭바가 낫다).
- 구현 주의: 폭은 화면의 80% 이하, 최대 약 320px. 뒤 배경에 어두운 스크림을 깔고 눌러 닫게 한다. 열리면 포커스를 안으로 옮기고 Esc나 뒤로 가기로 닫힌다. 현재 위치 항목을 강조.
- 비슷한 것: 사이드바 레이아웃(layout.md, 항상 펼쳐진 형태), Hidden navigation(layout.md).

### 브레드크럼 (Breadcrumb)
- 무엇: 홈에서 현재 페이지까지의 경로를 `홈 > 카테고리 > 상품`처럼 보여 주는 링크 줄.
- 언제: 계층이 깊은 웹사이트(문서, 쇼핑, 관리자)에서 위치 파악과 상위 이동이 필요할 때.
- 피할 때: 계층이 2단계 이하이거나 계층이 없는 앱 흐름, 모바일 앱의 기본 이동(뒤로 가기가 대신한다).
- 구현 주의: 현재 페이지는 링크가 아닌 글자로 두고 `aria-current="page"`. 경로가 길면 가운데를 줄이고(…) 첫 단계와 마지막 단계는 남긴다. 모바일에서는 바로 위 한 단계만 `< 상위`로 줄이는 방법이 있다.
- 비슷한 것: 뒤로 가기(이전 화면으로, 경로 전체가 아니다).

### 고정 헤더 (Sticky header)
- 무엇: 스크롤해도 화면 위에 남아 제목, 검색, 주요 행동을 유지하는 상단 바.
- 언제: 긴 목록이나 문서에서 검색, 필터, 뒤로 가기에 항상 접근해야 할 때.
- 피할 때: 화면이 낮아 본문이 가려질 때. 스크롤을 내릴 때만 숨기는 방식을 고려한다.
- 구현 주의: 높이 56px 안팎(모바일 44~56px). 스크롤 전엔 투명, 스크롤 후엔 배경과 구분선이나 약한 그림자를 더하는 전환을 주기도 한다. 앵커 이동 시 `scroll-margin-top`. 상태 표시줄 영역을 비운다.
- 비슷한 것: Fixed navigation(layout.md, 웹 사이트 전역 메뉴 관점).

### 플로팅 버튼 (Floating action button)
- 무엇: 콘텐츠 위에 떠서 화면의 주 행동 하나를 가리키는 원형(또는 확장형) 버튼.
- 언제: 새로 만들기, 글쓰기, 추가처럼 화면에서 가장 자주 하는 단일 행동.
- 피할 때: 화면에 주 행동이 여러 개일 때, 하단 콘텐츠를 가릴 때, 삭제 같은 파괴적 행동.
- 구현 주의: 지름 56px(작은 것 40px), 우하단에서 16px 안쪽. 탭바와 겹치면 탭바 위로 올린다. 스크롤을 내리면 줄이거나 숨기고 올리면 보인다. 아이콘만 쓸 때 `aria-label` 필수. 목록 끝 항목을 가리지 않도록 하단 패딩을 더한다.
- 비슷한 것: FAB vs 아이콘 버튼([confusable-pairs.md](confusable-pairs.md)), Center FAB(하단 메뉴 스타일 절).

### 페이지네이션 (Pagination)
- 무엇: 긴 목록을 페이지 번호나 이전·다음 버튼으로 나눠 보여 주는 방식.
- 언제: 원하는 위치로 돌아가거나 위치 감각이 중요한 검색 결과, 관리자 표, 푸터에 도달해야 하는 페이지.
- 피할 때: 짧은 목록, 모바일 피드(더 보기나 무한 스크롤).
- 구현 주의: 터치 영역 44px 이상, 현재 페이지 표시, 처음과 끝 이동, 페이지 수가 많으면 생략 표기(1 … 5 6 7 … 20). 페이지는 URL에 반영해 새로고침과 공유가 되게 한다. `nav aria-label="페이지"`.
- 비슷한 것: 무한 스크롤(위치 감각과 푸터 접근이 약하다).

### 무한 스크롤 (Infinite scroll)
- 무엇: 끝에 가까워지면 다음 항목을 자동으로 이어 불러오는 목록.
- 언제: 소셜 피드, 사진 모음처럼 끝이 없고 훑어 보는 콘텐츠.
- 피할 때: 푸터나 특정 항목을 찾아야 할 때, 목적이 분명한 검색. 항목 위치로 돌아와야 하는 화면.
- 구현 주의: 뒤로 가기 후 스크롤 위치와 불러온 목록을 복원한다. 불러오는 중에는 하단에 스켈레톤이나 스피너, 실패 시 재시도 버튼. 일정 개수마다 "더 보기" 버튼으로 끊으면 푸터에 닿을 수 있다. 가상화로 DOM 수를 제한한다.
- 비슷한 것: 페이지네이션, 당겨서 새로고침(gestures.md).

### 뒤로 가기 (Back navigation)
- 무엇: 직전 화면이나 상위 화면으로 돌아가는 동작(상단 왼쪽 화살표, 시스템 뒤로, 가장자리 스와이프).
- 언제: 푸시로 들어온 모든 하위 화면.
- 피할 때: 최상위 탭 화면에는 두지 않는다. 입력 도중 이탈이 데이터 손실을 일으키면 확인 없이 돌아가지 않는다.
- 구현 주의: 아이콘 터치 영역 44~48px, 위치는 왼쪽 위(좌우 반전 언어는 반대). 라벨 `이전` 같은 `aria-label`. 시스템 뒤로 가기와 같은 결과를 내야 한다. 저장하지 않은 변경이 있으면 폐기 확인을 띄운다.
- 비슷한 것: 브레드크럼(경로 전체), Edge swipe(gestures.md).

## B. 모바일 하단 메뉴 스타일 11종

공통 팁: 항목은 4~5개, 활성 상태는 분명하게, 아이콘 스타일 통일, 최소 탭 영역 48x48px, 작은 마이크로 인터랙션을 더한다. 탭 안쪽 위아래 패딩은 [spacing.md](spacing.md)(16px)를 본다. 공통 위험은 하단 안전 영역과 홈 인디케이터 겹침.

### Minimal clean (미니멀 클린)
- 무엇: 배경 하나, 가는 구분선, 단색 아이콘과 라벨로만 이루어진 가장 기본적인 막대.
- 언제: 어떤 제품이든 기본값이 필요할 때, 콘텐츠가 주인공일 때.
- 피할 때: 브랜드 개성이 필요한 소비자 앱(밋밋해 보일 수 있다).
- 구현 주의: 활성은 색과 아이콘 채움을 같이 바꾼다. 비활성 아이콘 대비도 3:1 이상. 높이 56~64px에 안전 영역 추가.

### Glassmorphism (글래스모피즘)
- 무엇: 반투명 흐림 배경 위에 아이콘을 둔 막대. 스타일 일반론은 [styles.md](styles.md).
- 언제: 뒤에 이미지나 색이 있는 화면, 앱이 가벼운 분위기일 때.
- 피할 때: 뒤 콘텐츠가 복잡한 텍스트일 때. 아이콘과 라벨 대비가 뒤 배경에 따라 흔들린다.
- 구현 주의: `backdrop-filter: blur(16~24px)` + 배경 알파 0.6~0.8. 미지원 브라우저용으로 불투명 대체 배경을 지정한다. 어떤 배경 위에서도 아이콘 대비 3:1 확인.

### Floating (Detached, 떠 있는 막대)
- 무엇: 화면 아래 가장자리에서 떨어져 모서리가 둥근 알약 모양으로 떠 있는 막대.
- 언제: 현대적 인상이 필요한 앱, 콘텐츠가 막대 뒤로 흐르는 화면.
- 피할 때: 콘텐츠가 막대에 가려져 마지막 항목을 못 누를 수 있는 목록 화면에서 하단 패딩 없이 쓸 때.
- 구현 주의: 좌우 16~24px, 하단 12~16px 띄우고 안전 영역을 더한다. 그림자는 약하게. 스크롤 콘텐츠에 막대 높이만큼 하단 패딩.

### Neumorphism (뉴모피즘)
- 무엇: 배경과 같은 색에 안쪽·바깥쪽 그림자로 눌린 듯 돋은 듯 표현한 막대. 스타일 일반론은 [styles.md](styles.md).
- 언제: 장식적 목업, 단순한 기능의 제품.
- 피할 때: 대부분의 실제 제품. 활성과 비활성 구분이 어렵고 대비가 낮아 접근성에서 위험하다.
- 구현 주의: 활성 항목은 그림자만이 아니라 색이나 아이콘 채움으로 구분. 아이콘 대비 3:1 확보 가능한지 먼저 계산한다.

### Pill highlight (알약 강조)
- 무엇: 활성 탭 뒤에 알약 모양 배경을 깔아 현재 위치를 보여 주는 막대.
- 언제: 활성 상태를 분명하게 보이고 싶을 때. 대부분의 모던 앱에 안전한 선택.
- 피할 때: 항목이 5개를 넘어 알약이 좁아질 때.
- 구현 주의: 알약 배경과 아이콘 대비를 따로 확인(활성 아이콘이 배경 위에서 4.5:1 또는 최소 3:1). 모션은 [Sliding pill](#sliding-pill-알약-슬라이드)과 연결된다.

### Center FAB (중앙 강조 버튼)
- 무엇: 가운데 항목만 크고 도드라진 버튼으로 만들어 핵심 행동(추가, 촬영)을 강조한 막대.
- 언제: 앱의 대표 행동이 분명할 때(글쓰기, 거래, 스캔).
- 피할 때: 가운데 항목이 단순한 화면 이동일 때. 항목 수가 짝수가 되면 가운데가 없다.
- 구현 주의: 일반 탭 4개 + 가운데 1개. 가운데는 지름 56px 안팎으로 막대 위로 약간 돌출. 왼쪽·오른쪽 대칭을 맞춘다. 접근성 라벨 필수.

### Gradient bold (그라디언트 강조)
- 무엇: 그라디언트 배경이나 그라디언트 활성 표시로 강한 색감을 준 막대.
- 언제: 게임, 엔터테인먼트처럼 감정과 브랜드 개성이 중요한 앱.
- 피할 때: 업무·금융 앱, 라벨 글자가 그라디언트 위에서 대비가 흔들릴 때.
- 구현 주의: 그라디언트 위 글자 대비는 가장 밝은 지점 기준으로 4.5:1 확인. 그라디언트는 두 색, 인접 색상 위주로.

### Outline icons (선 아이콘)
- 무엇: 비활성은 선 아이콘, 활성은 채움 아이콘으로 바꾸는 가벼운 막대.
- 언제: 정돈된 인상이 필요하고 활성 구분이 아이콘만으로 가능할 때.
- 피할 때: 선 굵기가 아이콘마다 다른 아이콘 세트를 섞을 때.
- 구현 주의: 같은 아이콘 세트에서 선 굵기 1.5~2px로 통일. 선 아이콘 비활성 대비 3:1 이상. 채움과 선 두 버전이 모두 있는 세트를 고른다.

### Tab with indicator (표시 막대 탭)
- 무엇: 활성 탭 위나 아래에 짧은 막대나 점을 두어 현재 위치를 표시하는 막대.
- 언제: 위치를 명확히 하되 장식은 적게 하고 싶을 때. 상단 탭의 밑줄과 같은 문법.
- 피할 때: 표시 막대가 너무 가늘어(1px) 놓칠 때.
- 구현 주의: 막대 두께 2~4px, 항목 폭의 40~60% 길이. 막대 이동에 150~250ms ease-out. 탭 인디케이터 일반론은 [indicators-completion.md](indicators-completion.md).

### Curved background (곡선 배경)
- 무엇: 막대 배경이 활성 탭 위치에서 곡선으로 움푹 파이거나 솟아 보이는 막대.
- 언제: 브랜드 개성을 모션과 함께 보여 주는 소비자 앱, 항목 4~5개.
- 피할 때: 항목 수가 유동적이거나 태블릿·가로 모드 대응이 중요할 때. 곡선 계산 때문에 유지보수가 어렵다.
- 구현 주의: SVG path나 clip-path로 만든다. 곡선 반경과 막대 높이를 변수화한다. 접근성 라벨과 포커스 링은 활성 항목 위치와 맞춘다. 모션은 [Floating notch](#floating-notch-떠다니는-홈).

### Dock style (iOS 독 스타일)
- 무엇: iOS의 독처럼 둥근 반투명 컨테이너에 큰 아이콘을 담고, 선택·터치 시 확대되는 막대.
- 언제: 아이콘이 인지하기 쉬운 앱 런처형 화면, Apple 플랫폼 느낌.
- 피할 때: 라벨이 꼭 필요한 정보 구조(라벨 없이 아이콘만으론 의미가 모호하다).
- 구현 주의: 아이콘 약 48~56px에 간격 12~16px. 확대 모션은 스프링 느낌으로 짧게. 라벨을 숨긴다면 `aria-label`과 길게 눌러 보는 툴팁을 둔다.

## C. 탭 바 전환 모션 6종

공통: 지속 시간 200~400ms, 이징은 ease-out이나 약한 스프링. `prefers-reduced-motion`이면 위치만 즉시 바꾸고 색 변화만 남긴다. 탭 이동은 모션이 끝나기를 기다리지 않고 바로 반응해야 한다.

### Sliding pill (알약 슬라이드)
- 무엇: 탭을 누르면 활성 알약이 늘어나며 새 위치로 미끄러지는 모션.
- 언제: 알약 강조 막대([Pill highlight](#pill-highlight-알약-강조))의 기본 모션.
- 구현 주의: 알약 하나를 `transform: translateX`와 `scaleX`로 움직여 구현하고(레이아웃을 건드리지 않는다) 탭마다 배경을 따로 껐다 켜지 않는다. 300ms 안팎. `scaleX`는 모서리 반경이 늘어나므로 알약 양 끝이 뭉개지면 알약 배경만 절대 위치 요소로 두고 폭 변화를 쓰는 예외를 허용한다([motion.md](motion.md) 공통 기준).

### Liquid bulge (액체 부풀기)
- 무엇: 활성 탭 아래의 막대가 액체처럼 부풀며 이동하는 모션.
- 언제: 개성 있는 소비자 앱, 표시 막대 탭 스타일([Tab with indicator](#tab-with-indicator-표시-막대-탭)).
- 구현 주의: SVG 필터나 path 보간을 쓰면 성능 부담이 크다. 모바일 저사양에서 프레임이 끊기면 단순 이동으로 대체한다. 400ms 이내.

### Floating notch (떠다니는 홈)
- 무엇: 막대의 곡선 홈을 따라 공(활성 표시)이 이동하는 모션.
- 언제: 곡선 배경 막대([Curved background](#curved-background-곡선-배경))와 함께.
- 구현 주의: 홈의 위치와 공의 위치를 같은 변수로 움직여 어긋남을 막는다. 아이콘은 공 안에서 약간 올라간다. 300~400ms.

### Icon fill (아이콘 채움)
- 무엇: 활성 아이콘이 중심에서부터 채워지고 아래에 작은 점이 생기는 모션.
- 언제: 선 아이콘 막대([Outline icons](#outline-icons-선-아이콘))에 가장 가볍고 안전한 모션.
- 구현 주의: 선 아이콘과 채움 아이콘 두 장을 겹쳐 clip이나 opacity로 전환한다. 150~250ms. 점은 색 외에 위치로도 구분되므로 접근성 이점이 있다.

### Expanding label (라벨 확장)
- 무엇: 활성 탭이 알약으로 커지면서 라벨이 나타나고 비활성 탭은 아이콘만 남기는 모션.
- 언제: 공간이 좁은데 활성 항목의 이름을 보여 주고 싶을 때.
- 피할 때: 라벨이 길거나 번역으로 길어질 때. 활성 탭 폭이 다른 탭 폭을 흔든다.
- 구현 주의: 활성 탭 폭의 최대값을 정해 레이아웃이 흔들리지 않게 한다. 비활성 탭의 이름은 `aria-label`로 항상 제공. 250~350ms.

### Bubble float (거품 떠오름)
- 무엇: 활성 아이콘이 위로 떠오르고 작은 거품 입자가 올라가는 모션.
- 언제: 장난스러운 브랜드, 게임이나 어린이 앱.
- 피할 때: 업무·금융 앱, 반복 사용이 잦은 곳(탭을 누를 때마다 반복되어 피로하다).
- 구현 주의: 입자는 5개 이하로 600ms 안에 끝낸다. `prefers-reduced-motion`이면 입자를 생략하고 아이콘 색만 바꾼다. 터치 반응을 막지 않는다.
