# 입력 (버튼 상태 9종, 텍스트 필드 상태·셀렉트, 텍스트 필드 모션 6종)

상태 누락은 비디자이너가 가장 자주 놓치는 부분이다. 모든 상호작용 요소는 [quality-rules.md](quality-rules.md)의 상태 목록을 채운다.

## A. 버튼 상태 9종

공통: 상태마다 색 하나에만 의존하지 않는다. 터치 영역 최소 44~48px, 버튼 사이 간격 12px([spacing.md](spacing.md)). 상태 전환은 100~200ms.

### 기본 (Default)
- 무엇: 아무 조작도 하지 않았을 때의 모양.
- 언제: 모든 버튼의 기준 상태. 주 버튼은 채움, 보조는 윤곽, 약한 행동은 글자 버튼으로 위계를 나눈다.
- 구현 주의: 한 화면에 채움 버튼은 하나. 라벨은 동사로 구체적으로(`저장`, `주문하기`). 글자와 배경 대비 4.5:1.

### 호버 (Hover)
- 무엇: 마우스 포인터를 올렸을 때의 모양. 터치 기기에는 없다.
- 언제: 데스크톱 웹에서 클릭 가능함을 알릴 때.
- 구현 주의: 색을 한 단계 밝게/어둡게. 호버에만 중요한 정보를 두지 않는다. `@media (hover: hover)`로 감싸 터치에서 눌린 뒤 호버 상태가 남는 문제를 막는다.

### 눌림 (Pressed)
- 무엇: 누르는 동안의 모양(active).
- 언제: 눌렀다는 즉각적 확인이 필요한 모든 버튼, 특히 터치.
- 구현 주의: 색을 한 단계 더 진하게 하거나 `scale(0.97)` 정도로 살짝 눌린 느낌. 100ms 안에 반응. 눌림 표시가 손가락에 가려질 수 있어 색 변화를 크게 한다.

### 포커스 (Focus)
- 무엇: 키보드나 보조기기로 선택된 모양.
- 언제: 모든 상호작용 요소. 접근성 필수.
- 구현 주의: `:focus-visible`에 2px 이상 윤곽선과 배경 대비 3:1 이상, `outline-offset` 2px. `outline: none`만 쓰고 대체를 안 두는 것이 가장 흔한 실수.

### 비활성 (Disabled)
- 무엇: 지금은 누를 수 없는 상태.
- 언제: 필수 입력이 안 채워진 제출 버튼 등.
- 피할 때: 왜 못 누르는지 알 수 없을 때. 가능하면 활성으로 두고 눌렀을 때 인라인 오류로 이유를 알린다.
- 구현 주의: 흐리게(opacity 0.4~0.5) + `cursor: not-allowed`. 비활성은 대비 규칙의 예외지만 흐린 정도가 너무 높으면 읽을 수 없다. `disabled` 속성은 포커스를 막으므로 `aria-disabled`로 이유를 읽어 주는 방식도 쓴다.

### 로딩 (Loading)
- 무엇: 요청 처리 중인 상태. 버튼 안에 스피너를 넣고 중복 클릭을 막는다.
- 언제: 서버 요청을 보내는 제출, 결제, 저장 버튼.
- 구현 주의: 버튼 폭을 유지해 레이아웃이 흔들리지 않게 한다. 라벨을 `저장 중…`으로 바꾸거나 스피너 옆에 남긴다. `aria-busy="true"`. 2초 넘게 걸리면 단계 안내를 더한다. 같은 항목: [로딩 버튼](empty-loading.md).

### 성공 (Success)
- 무엇: 처리가 끝났음을 버튼 자체가 보여 주는 상태(체크 아이콘, 초록색).
- 언제: 저장, 복사, 전송처럼 결과가 즉시 나오는 행동.
- 구현 주의: 1~2초 유지 후 기본으로 복귀. 초록만이 아니라 체크 아이콘과 라벨 변경(`저장됨`)을 쓴다. 연출은 [버튼 모핑](indicators-completion.md).

### 오류 (Error)
- 무엇: 처리에 실패해 버튼이 오류를 알리는 상태.
- 언제: 요청 실패 직후 다시 시도를 유도할 때.
- 구현 주의: 버튼만 붉게 바꾸지 말고 이유와 재시도를 근처 [인라인 오류](feedback.md)로 설명한다. 라벨을 `다시 시도`로 바꾸는 방식이 흔하다.

### 선택됨 (Selected)
- 무엇: 토글형 버튼이나 선택 그룹에서 켜진 상태.
- 언제: 필터 칩, 보기 전환, 좋아요처럼 켜짐과 꺼짐이 있는 버튼.
- 구현 주의: 배경 채움과 체크나 굵기 같은 두 가지 이상의 단서. `aria-pressed="true"` 또는 `aria-selected`. 선택됨과 호버/포커스가 겹칠 때의 모양도 정한다.

## B. 텍스트 필드와 셀렉트

### 텍스트 필드 상태 (Text field states)
- 무엇: 입력 칸이 가지는 상태 묶음. 기본, 포커스, 입력됨, 오류, 비활성에 더해 읽기 전용, 성공이 있다.
- 언제: 모든 폼.
- 피할 때: 플레이스홀더를 라벨로 대신하는 구성. 입력을 시작하면 안내가 사라진다.
- 구현 주의: 라벨은 칸 위에 항상 보이게(플로팅 라벨도 입력 후 작게 남는다). 높이 44~56px, 글자 16px 이상(iOS 줌 방지). 포커스는 테두리 2px에 색 변화, 오류는 테두리와 아이콘, 문구 모두. 도움말은 칸 아래에 두고 오류가 나면 같은 자리를 오류 문구로 바꾼다. 적절한 `type`, `inputmode`, `autocomplete`로 모바일 키보드를 맞춘다.
- 비슷한 것: 플레이스홀더 vs 라벨([confusable-pairs.md](confusable-pairs.md)), 인라인 오류([feedback.md](feedback.md)).

### 셀렉트 (Select)
- 무엇: 정해진 선택지 중 하나(드물게 여러 개)를 목록에서 고르는 입력.
- 언제: 선택지가 대략 5~15개이고 공간이 부족할 때(국가, 연도, 정렬).
- 피할 때: 선택지가 2~4개(라디오나 세그먼트), 15개를 넘는 목록(검색 가능한 콤보박스), 메뉴 명령 모음(드롭다운 메뉴).
- 구현 주의: 모바일에서는 기본 `select`가 시스템 피커를 열어 가장 안정적이다. 직접 만들면 키보드(위아래, Enter, Esc, 글자 입력 이동)와 `aria-expanded`를 구현해야 한다. 현재 선택값을 항상 보이게, 기본값이 없으면 `선택해 주세요` 안내.
- 비슷한 것: 드롭다운 메뉴 vs 셀렉트([confusable-pairs.md](confusable-pairs.md)).

## C. 텍스트 필드 모션 6종

공통: 보조 연출이므로 입력 자체를 막거나 늦추지 않는다. `prefers-reduced-motion`이면 전환 없이 결과 상태만 보인다.

### OTP code (인증 코드)
- 무엇: 인증 번호를 칸 하나에 한 글자씩 입력하고 자동으로 다음 칸으로 넘어가는 입력.
- 언제: 문자·이메일 인증 6자리 안팎.
- 구현 주의: 칸 여러 개로 보여도 접근성을 위해 하나의 입력으로 만들거나 `autocomplete="one-time-code"`를 지정해 문자 자동 채움이 되게 한다. 붙여넣기 시 전체 분배, 백스페이스 시 앞 칸 이동, 칸 크기는 44px 이상. 숫자 키패드(`inputmode="numeric"`).

### Card number (카드 번호)
- 무엇: 숫자를 4자리씩 묶어 보여 주고 입력이 끝나면 만료일 칸이 이어지는 입력.
- 언제: 결제 폼.
- 구현 주의: 입력 중 공백 삽입으로 커서가 튀지 않게 한다. `autocomplete="cc-number"`, `cc-exp`. 카드 종류 아이콘은 보조 정보로만. 만료일 칸으로 자동 이동하되 사용자가 되돌아가 고칠 수 있게 한다. 카드 번호는 로그와 분석 도구에 남기지 않는다.

### Strength meter (강도 표시기)
- 무엇: 비밀번호가 입력되는 동안 4단계 막대가 채워지며 색이 바뀌어 안전도를 보여 주는 표시.
- 언제: 회원가입, 비밀번호 변경.
- 피할 때: 단순히 막대만 보여 주고 어떻게 고쳐야 하는지 알려 주지 않을 때.
- 구현 주의: 색만이 아니라 `약함/보통/강함` 글자를 함께 쓴다. 규칙 나열(대문자 포함 등)보다 길이를 우선 평가한다. `aria-live="polite"`로 단계 변경을 알린다. 비밀번호 보기 토글을 함께 둔다. 같은 형태의 막대는 [indicators-completion.md](indicators-completion.md)에서 이 항목을 가리킨다.
- 비슷한 것: 프로그레스 바(진행 상태를 보여 주지만 강도가 아니다).

### Auto grow (자동 높이)
- 무엇: 줄이 늘어날수록 입력 칸 높이가 따라 커지는 여러 줄 입력.
- 언제: 채팅 입력, 댓글, 메모.
- 구현 주의: 최대 높이(예: 5~8줄)를 두고 넘으면 내부 스크롤. `field-sizing: content`는 지원이 제한적이므로 대체 구현을 준비한다. 높이가 바뀔 때 주변 레이아웃이 튀지 않게 한다. 전송 후 한 줄로 되돌린다.

### Tag input (태그 입력)
- 무엇: 단어를 입력하고 Enter나 쉼표를 누르면 칩으로 바뀌며 x로 지울 수 있는 입력.
- 언제: 태그, 이메일 수신자 여러 명, 관심사 선택.
- 구현 주의: 칩의 x 터치 영역 44px 이상, 백스페이스로 마지막 칩 삭제, 붙여넣기로 여러 개 분리. 중복과 개수 제한은 인라인 안내. 각 칩에 `aria-label="삭제"` 이름.

### Ghost complete (고스트 자동완성)
- 무엇: 입력한 글자 뒤에 회색으로 자동완성 제안을 보여 주고 Tab으로 확정하는 입력.
- 언제: 명령 입력, 검색창, 이메일 도메인 완성처럼 입력이 예측 가능한 곳.
- 피할 때: 모바일 터치 중심 화면(Tab 키가 없다. 제안 칩이나 → 버튼을 둔다).
- 구현 주의: 제안 글자는 입력 글자와 같은 폰트와 위치에 겹쳐 대비를 낮게(그래도 읽을 수 있게). 확정 방법을 힌트로 알린다(`Tab`). 스크린 리더에는 `aria-autocomplete`와 제안을 `aria-live`로 전달하는 방안.
