# 화면 하나를 만들 때의 결정 순서

화면을 만들 때 어떤 것부터 정하는지의 순서다. 앞 단계의 결정이 뒤 단계의 선택지를 좁히므로 이 순서를 지킨다. propose 스킬은 이 목록에서 해당 화면에 필요한 지점만 골라 시안을 만들고, build 스킬은 기록이 없을 때 이 순서대로 선택을 내린다.

각 지점에서 볼 파일과 건너뛰어도 되는 조건을 적었다. 건너뛰어도 되는 조건은 "그 지점에서 새로 고를 것이 없을 때"를 뜻한다.

| # | 결정 지점 | 정하는 것 | 볼 레퍼런스 | 건너뛰어도 되는 조건 |
|---|---|---|---|---|
| 1 | 목적과 주 행동 | 이 화면이 무엇을 위한 곳인지, 사용자가 가장 먼저 할 일 하나, 플랫폼(웹 또는 모바일) | [quality-rules.md](quality-rules.md)의 Q11 | 건너뛰지 않는다. 항상 먼저 정한다 |
| 2 | 레이아웃 | 화면의 큰 뼈대(열 구성, 히어로, 카드 격자, 대시보드 등) | [layout.md](layout.md) | 기존 레이아웃 틀(공통 쉘)이 정해져 있고 그 안에 내용만 채울 때 |
| 3 | 내비게이션 | 다른 화면으로 가는 방법(하단 탭, 상단 탭, 드로어, 뒤로 가기, 페이지네이션 등) | [navigation.md](navigation.md), [confusable-pairs.md](confusable-pairs.md)의 앱 바와 탭 바 | 앱 전체 내비게이션이 이미 있고 이 화면이 그 안의 하위 화면일 때(뒤로 가기만 확인) |
| 4 | 핵심 컴포넌트 | 주 내용을 보여 주고 입력받는 요소(카드와 리스트, 입력 칸, 셀렉트, 평점, 공유, 채팅 요소 등) | [inputs.md](inputs.md), [ratings-share.md](ratings-share.md), [ai-chat.md](ai-chat.md), [confusable-pairs.md](confusable-pairs.md) | 화면에 입력이나 선택 요소가 없는 정보 표시 화면일 때 |
| 5 | 상태 | 빈 화면, 로딩, 오류, 완료, 버튼과 입력 상태 | [empty-loading.md](empty-loading.md), [indicators-completion.md](indicators-completion.md), [inputs.md](inputs.md) | 서버 데이터가 없고 정적인 화면일 때(로딩과 빈 화면). 버튼과 입력 상태는 건너뛰지 않는다 |
| 6 | 피드백 | 행동의 결과를 알리는 방법(토스트, 스낵바, 배너, 모달, 인라인 오류 등)과 처음 사용자 안내 | [feedback.md](feedback.md), [onboarding.md](onboarding.md) | 사용자가 하는 쓰기·삭제 행동이 없는 읽기 전용 화면일 때 |
| 7 | 모션과 전환 | 화면 전환, 요소 등장, 제스처 | [motion.md](motion.md), [gestures.md](gestures.md) | 모션이 필요 없다고 정했을 때(그래도 `prefers-reduced-motion` 대응은 확인). 기본 전환만 쓰는 화면일 때 |
| 8 | 스타일과 간격 마감 | 디자인 스타일, 색, 반경, 그림자, 간격 체계 | [styles.md](styles.md), [spacing.md](spacing.md), [quality-rules.md](quality-rules.md) | 대상 레포에 스타일과 토큰이 이미 있을 때(스타일은 건너뛰고 간격과 규칙 점검만 한다) |

## 결정 지점별 메모

1. 목적과 주 행동: "이 화면에서 사용자가 첫 3초에 한 가지만 한다면 무엇인가"에 답할 수 있어야 한다. 답이 둘이면 화면을 나눈다. 플랫폼이 모바일이면 엄지 닿는 위치(하단)에 주 행동이 오게 설계한다.
2. 레이아웃: 콘텐츠 양과 성격(글, 이미지, 표, 목록)과 읽는 방식(훑기, 비교, 몰입)이 레이아웃을 정한다. 모바일은 거의 항상 한 열이므로 선택지는 순서와 묶음이다.
3. 내비게이션: 목적지 수와 사용 빈도로 정한다. 3~5개의 대등한 목적지는 하단 탭, 그보다 많으면 드로어나 더보기, 같은 화면의 보기 전환은 상단 탭이나 세그먼트.
4. 핵심 컴포넌트: 카드인지 리스트인지, 입력은 어떤 형식인지 등. 헷갈리는 쌍은 표에서 기준 한 줄로 결정한다.
5. 상태: 정상 화면 하나만 그리지 않는다. 빈 화면 최소 1개, 로딩 1개, 오류 1개를 정하고 propose에서는 시안에 반영한다.
6. 피드백: 행동마다 "결과를 어떻게 알리나"를 정한다. 되돌릴 수 있으면 스낵바, 가벼운 확인이면 토스트, 입력 오류면 인라인.
7. 모션과 전환: 위의 선택을 방해하지 않는 선에서 최소로. 지속 시간과 이징은 [motion.md](motion.md)의 공통 기준표.
8. 스타일과 간격 마감: 마지막에 한꺼번에 한다. 앞 단계에서 정한 구조 위에 색과 질감을 얹는다. 구조가 정해지기 전에 스타일을 고르면 구조 선택이 스타일에 끌려간다.
