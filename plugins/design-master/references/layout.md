# 레이아웃 (웹 레이아웃 12종, 화면 배치 9종)

화면의 큰 뼈대를 정하는 항목이다. 같은 이름이 두 곳에 나오면(Split screen, Magazine, Z 패턴) 본문은 앞쪽 한 곳에만 있다.
간격 수치는 [spacing.md](spacing.md), 접근성과 반응형 점검은 [quality-rules.md](quality-rules.md)를 본다.

## A. 웹 레이아웃 12종

### Two-column (2열)
- 무엇: 화면을 두 개의 세로 영역으로 나눠 한쪽엔 본문, 다른 쪽엔 보조 정보(이미지, 목차, 요약)를 두는 구성.
- 언제: 설명과 시각 자료를 함께 보여 줄 때, 본문 옆에 목차나 구매 카드를 고정할 때.
- 피할 때: 좁은 화면에서 비율을 유지하려 할 때. 모바일은 한 열로 쌓고 순서를 정해야 한다.
- 구현 주의: 비율은 6:4 또는 7:3처럼 주종이 분명해야 한다. 본문 줄 길이는 라틴 문자 기준 45~75자, 한글은 한 줄 30~40자 안팎. `grid-template-columns`에 minmax를 쓰고, 보조 열을 sticky로 둘 때 top 값을 고정 헤더 높이만큼 띄운다.
- 비슷한 것: Split screen(두 영역이 대등하고 화면 전체를 쓴다), Sidebar layout(보조 열이 내비게이션 역할).

### Split screen (스플릿)
- 무엇: 화면을 두 개의 큰 면으로 반씩 나눠 서로 다른 내용이나 선택지를 대등하게 보여 주는 구성.
- 언제: 로그인 화면(폼과 브랜드 이미지), 두 선택지 비교, 랜딩의 첫 화면.
- 피할 때: 내용이 한쪽으로 쏠릴 때, 모바일 폭. 모바일에서는 위아래로 쌓거나 한쪽만 남긴다.
- 구현 주의: 높이는 `min-height: 100dvh`를 쓰고 모바일 주소창 변화를 고려한다. 양쪽 모두 텍스트가 올라가면 각각 대비를 따로 확인한다. 이미지 쪽은 alt를 비우거나 장식 처리한다.
- 비슷한 것: Two-column(주종 관계가 있는 구성).

### Z-shape (지그재그)
- 무엇: 시선이 좌상단에서 우상단, 대각선으로 좌하단, 우하단으로 Z 모양으로 움직인다는 점을 이용해 요소를 배치하는 구성.
- 언제: 콘텐츠가 적고 행동 유도가 하나인 랜딩. 로고, 메뉴, 핵심 문구, 버튼 순서가 분명할 때.
- 피할 때: 글이 많은 페이지. 글이 많으면 시선이 F자로 읽힌다(F-shape).
- 구현 주의: 이미지와 글을 번갈아 좌우로 놓는 지그재그 반복에서는 모바일에서 이미지와 글의 순서를 항상 같게 쌓는다. 시선 끝(우하단)에 주 버튼을 둔다.
- 비슷한 것: Z 패턴(화면 배치 절에서 이 항목을 가리킨다).

### Asymmetrical (비대칭)
- 무엇: 좌우 무게를 일부러 다르게 두고 여백과 크기 대비로 균형을 잡는 구성.
- 언제: 브랜드 인상이 중요한 소개 페이지, 포트폴리오, 편집 느낌이 필요한 화면.
- 피할 때: 폼, 표, 업무용 화면처럼 정보를 빠르게 훑는 화면.
- 구현 주의: 12열 격자 위에서 열을 비우는 방식으로 만들면 정렬선이 유지된다. 시각적 무게가 한쪽에 몰려도 읽는 순서는 DOM 순서와 같아야 한다.
- 비슷한 것: Magazine(여러 크기의 블록을 격자 위에 섞는다).

### F-shape (F 패턴)
- 무엇: 사용자가 위쪽 가로줄을 읽고, 조금 아래에서 한 번 더 가로로 읽은 뒤 왼쪽 가장자리를 따라 내려가며 훑는 경향에 맞춘 구성.
- 언제: 글, 목록, 검색 결과처럼 텍스트가 많은 화면.
- 피할 때: 감정적 몰입이나 하나의 행동을 강조할 화면(Z-shape이 맞다).
- 구현 주의: 중요한 단어를 줄 맨 앞에 둔다. 제목, 소제목, 굵은 단어로 왼쪽 가장자리에 읽을 거리를 만든다. 문단은 짧게, 한 문단에 한 생각.
- 비슷한 것: Z-shape(시선 경로가 다르다).

### Featured image or video (대표 이미지·영상)
- 무엇: 화면 상단이나 중심에 큰 이미지나 영상을 두고 그 위나 아래에 핵심 문구를 얹는 구성.
- 언제: 제품, 장소, 이야기를 한눈에 전달해야 할 때. Hero section의 한 형태.
- 피할 때: 이미지가 정보를 대신하지 못하거나 로딩이 느린 환경. 자동 재생 영상은 데이터와 배터리 부담이 크다.
- 구현 주의: 이미지 위 텍스트는 어두운 그라디언트 오버레이로 대비 4.5:1을 확보한다. 영상은 `muted autoplay playsinline loop`와 포스터 이미지를 쓰고 정지 버튼을 제공한다. `prefers-reduced-motion`이면 정지 상태로 둔다. 종횡비를 지정해 레이아웃 흔들림을 막는다.
- 비슷한 것: 히어로(화면 배치 절).

### Card or block (카드·블록)
- 무엇: 정보를 같은 모양의 사각형 묶음으로 나눠 격자에 배열하는 구성.
- 언제: 서로 독립된 항목이 여러 개이고 훑어보며 고를 때(상품, 글, 프로젝트).
- 피할 때: 항목 간 비교가 핵심일 때(표나 리스트가 낫다). 카드 안에 카드를 넣는 중첩.
- 구현 주의: 카드의 높이, 모서리 반경, 그림자를 하나로 통일한다. 카드 전체가 링크면 링크는 하나만 두고 안에 또 다른 버튼을 넣지 않는다. 카드 사이 간격은 12~24px 범위에서 하나로.
- 비슷한 것: Card grid(화면 배치 절, 같은 패턴의 격자 구성), 카드 vs 리스트([confusable-pairs.md](confusable-pairs.md)).

### Magazine (매거진)
- 무엇: 크기가 다른 블록(큰 대표 기사, 작은 기사, 사이드 목록)을 격자 위에 섞어 위계를 만드는 편집형 구성.
- 언제: 콘텐츠 양이 많고 우선순위가 있는 뉴스, 블로그, 커뮤니티 홈.
- 피할 때: 콘텐츠가 몇 개 안 되거나 모두 같은 중요도일 때.
- 구현 주의: 큰 블록 1개, 중간 2~3개, 작은 것 나머지처럼 크기 단계를 3단계 이하로 둔다. 격자의 열 수를 유지해 정렬선을 맞춘다. 모바일에서는 큰 블록 다음에 작은 블록을 목록으로 쌓는다.
- 비슷한 것: Masonry(높이만 다르고 위계는 없다), Card or block(크기가 모두 같다).

### Fixed navigation (고정 내비게이션)
- 무엇: 스크롤해도 화면 위(또는 옆, 아래)에 계속 보이는 메뉴.
- 언제: 이동 빈도가 높고 페이지가 긴 서비스, 앱 형태의 웹.
- 피할 때: 가로가 좁고 세로 공간이 귀한 화면(모바일 가로 모드, 읽기 중심 화면).
- 구현 주의: 높이는 56~72px 이하로 줄인다. `position: sticky`와 앵커 이동 시 `scroll-margin-top`을 함께 쓴다. 불투명 배경 또는 충분한 블러와 구분선으로 아래 글과 겹쳐 읽히지 않게 한다.
- 비슷한 것: 고정 헤더(navigation.md, 상단 바 자체의 동작), Hidden navigation(반대 접근).

### Masonry (벽돌형)
- 무엇: 폭은 같고 높이가 다른 카드를 빈틈 없이 열마다 쌓아 채우는 구성.
- 언제: 사진, 이미지 모음, 영감 보드처럼 높이가 제각각인 시각 콘텐츠.
- 피할 때: 글 중심 항목, 비교나 순서가 중요한 목록. 읽는 순서가 열 단위로 흩어진다.
- 구현 주의: CSS `column-count`는 위에서 아래로 열을 채워 순서가 직관과 다르다. 순서가 중요하면 JS 배치나 열별 분배를 쓴다. 이미지 종횡비를 미리 알려 로딩 중 점프를 막는다. 키보드 탭 순서와 화면 순서를 맞춘다.
- 비슷한 것: Card or block(높이 균일), Magazine(위계 있음).

### Hidden navigation (숨김 내비게이션)
- 무엇: 평소엔 메뉴를 감추고 아이콘이나 제스처로 열어 보이게 하는 구성(햄버거, 스크롤 시 숨김 헤더).
- 언제: 콘텐츠가 주인공인 화면, 메뉴 항목이 많거나 사용 빈도가 낮을 때.
- 피할 때: 핵심 이동이 자주 일어나는 서비스. 숨기면 발견성과 이동률이 떨어진다.
- 구현 주의: 열기 버튼에 `aria-expanded`, `aria-controls`를 달고 열릴 때 포커스를 메뉴로 옮긴다. Esc로 닫힌다. 스크롤 방향으로 숨기는 헤더는 위로 조금만 올려도 다시 나오게 한다.
- 비슷한 것: 드로어(navigation.md), 햄버거 vs 케밥([confusable-pairs.md](confusable-pairs.md)).

### Interactive (인터랙티브)
- 무엇: 스크롤, 클릭, 드래그에 따라 내용이 바뀌거나 펼쳐지며 사용자가 직접 조작하며 읽는 구성.
- 언제: 제품 설명을 단계별로 보여 줄 때, 계산기나 비교 도구, 데이터 탐색.
- 피할 때: 정보를 빨리 찾아야 하는 화면, 저사양 기기, 접근성 요구가 높은 공공 서비스.
- 구현 주의: 모든 조작에 키보드 대안을 둔다. 스크롤을 가로채지 않는다(scroll hijacking 금지). 모션은 `prefers-reduced-motion`이면 끄거나 줄이고, 조작 결과는 URL이나 상태로 복구 가능하게 둔다.
- 비슷한 것: 모션 항목 전반([motion.md](motion.md)).

## B. 화면 배치 9종

### 히어로 (Hero section)
- 무엇: 페이지 맨 위에서 한 문장 제안, 보조 설명, 주 행동 버튼을 크게 보여 주는 영역.
- 언제: 랜딩, 앱 소개, 캠페인 페이지.
- 피할 때: 업무용 앱의 내부 화면. 도구 화면에서는 작업 공간이 먼저다.
- 구현 주의: 제목 한 개, 보조 문장 한두 줄, 주 버튼 하나, 보조 링크 하나까지. 첫 화면에서 다음 내용이 살짝 보이게 높이를 `100dvh`보다 약간 작게 한다. 이미지가 있으면 [Featured image or video](#featured-image-or-video-대표-이미지영상)의 오버레이 규칙을 따른다.
- 비슷한 것: Featured image or video(히어로를 이루는 시각 요소).

### 벤토 그리드 (Bento grid)
- 무엇: 크기가 다른 사각 타일을 도시락처럼 빈틈 없이 맞춰 짜고 각 타일에 특징 하나씩 담는 배치.
- 언제: 제품 기능 소개, 대시보드형 요약, 서로 다른 성격의 정보를 한 화면에 모을 때.
- 피할 때: 타일마다 정보 밀도와 중요도가 비슷할 때, 타일이 3개 이하일 때.
- 구현 주의: 타일 간격 하나(12~16px)와 모서리 반경 하나를 쓴다. `grid-template-areas`로 크기를 정하고 모바일에서는 한 열로 풀어 쌓는다. 타일 크기가 곧 중요도이므로 가장 큰 타일에 핵심을 둔다.
- 비슷한 것: Card grid(크기 균일), Masonry(높이만 다르다).

### 스플릿 (Split screen)
- 참조: 웹 레이아웃 절의 [Split screen](#split-screen-스플릿)과 같은 항목이다. 언제, 피할 때, 구현 주의는 그곳을 본다.

### 카드 그리드 (Card grid)
- 무엇: 같은 크기의 카드를 행과 열로 배열한 배치.
- 언제: 상품 목록, 템플릿 갤러리, 팀원 소개처럼 같은 종류의 항목이 많을 때.
- 피할 때: 항목마다 설명 길이가 크게 다를 때(카드 높이가 들쭉날쭉). 정렬·필터 중심의 업무 데이터(표).
- 구현 주의: `repeat(auto-fill, minmax(240px, 1fr))`처럼 최소 폭을 정해 열 수를 자동으로 바꾼다. 텍스트는 줄 수를 제한(line-clamp)하고 제목·가격 위치를 모든 카드에서 같게 한다. 로딩 중에는 같은 모양의 스켈레톤을 쓴다.
- 비슷한 것: Card or block(웹 레이아웃 절의 개념 설명).

### 사이드바 레이아웃 (Sidebar layout)
- 무엇: 좌측(드물게 우측)에 세로 메뉴나 필터를 고정하고 오른쪽에 본문을 두는 배치.
- 언제: 메뉴가 많은 관리자·설정·문서 화면, 필터가 많은 검색 결과.
- 피할 때: 모바일 주 화면(드로어나 하단 탭으로 바꾼다), 메뉴가 4~5개 이하일 때.
- 구현 주의: 폭은 보통 240~280px, 접힌 상태는 아이콘만 64~72px. 현재 위치를 배경과 굵기 두 가지로 표시한다. 본문과 사이드바를 각각 독립 스크롤로 둘 때 키보드 포커스가 갇히지 않게 한다.
- 비슷한 것: 드로어(같은 내용이 눌러서 나오는 형태), Two-column(보조 열이 내비게이션이 아닐 때).

### 매거진 (Magazine layout)
- 참조: 웹 레이아웃 절의 [Magazine](#magazine-매거진)과 같은 항목이다. 언제, 피할 때, 구현 주의는 그곳을 본다.

### 대시보드 (Dashboard)
- 무엇: 핵심 수치, 차트, 최근 활동을 한 화면에 모아 현재 상태를 한눈에 보여 주는 배치.
- 언제: 운영 현황, 분석, 관리 도구의 첫 화면.
- 피할 때: 사용자가 판단할 지표가 정해지지 않았을 때(모든 숫자를 늘어놓게 된다), 모바일에서 차트를 그대로 축소할 때.
- 구현 주의: 맨 위에 가장 중요한 수치 3~4개, 그 아래 추이, 맨 아래 상세 표 순서. 수치마다 단위, 기간, 비교 기준을 쓴다. 색만으로 좋고 나쁨을 전달하지 않고 화살표나 글자를 함께 쓴다. 빈 데이터, 로딩, 오류 상태를 위젯마다 둔다([empty-loading.md](empty-loading.md)).
- 비슷한 것: Bento grid(마케팅용 구성, 실시간 수치는 없다).

### Z 패턴 (Z-pattern)
- 참조: 웹 레이아웃 절의 [Z-shape](#z-shape-지그재그)와 같은 항목이다. 언제, 피할 때, 구현 주의는 그곳을 본다.

### 풀블리드 (Full bleed)
- 무엇: 이미지나 색 면이 좌우 여백 없이 화면 끝까지 닿는 배치.
- 언제: 사진이 주인공인 기사 상단, 구분 띠, 인용구 강조, 히어로 배경.
- 피할 때: 텍스트가 가장자리에 붙을 때. 본문은 항상 안쪽 여백을 유지한다.
- 구현 주의: 배경은 끝까지 채우고 내용은 `max-width` 컨테이너 안에 둔다. 가로 스크롤이 생기지 않게 `100vw` 대신 `100%`를 우선 쓴다(스크롤바 폭 때문에 넘친다). 모바일 노치 영역은 `env(safe-area-inset-*)`로 비운다.
