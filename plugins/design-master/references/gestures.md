# 제스처 (9종)

터치 화면에서 손가락으로 하는 조작이다. 공통 규칙: 제스처는 숨은 조작이므로 같은 일을 하는 눈에 보이는 버튼을 반드시 함께 둔다(접근성, 발견성). 같은 제스처를 화면마다 다른 뜻으로 쓰지 않는다. 시스템 제스처(가장자리 스와이프, 홈 제스처)와 충돌하지 않게 한다. 터치 타깃은 최소 44~48px.

### 탭 (Tap)
- 무엇: 화면을 한 번 짧게 누르는 기본 조작.
- 언제: 버튼, 링크, 항목 선택 등 모든 기본 행동.
- 피할 때: 오작동 위험이 큰 행동(삭제)을 탭 한 번으로 즉시 하는 것(확인이나 되돌리기 필요).
- 구현 주의: 터치 영역 44~48px, 눌림 즉시 반응(100ms 이내), 모바일 브라우저의 탭 지연은 `touch-action: manipulation`과 viewport 설정으로 막는다. 인접 타깃 사이 간격 8~12px.
- 비슷한 것: 두 번 탭, 길게 누르기.

### 길게 누르기 (Long press)
- 무엇: 화면을 0.5초 안팎 누르고 있는 조작. 부가 메뉴나 선택 모드를 연다.
- 언제: 항목의 컨텍스트 메뉴, 다중 선택 시작, 미리보기. 파워 사용자용 단축.
- 피할 때: 유일한 접근 경로로 쓰는 것(발견할 수 없다). 반드시 대체 경로 제공.
- 구현 주의: 기준 시간 약 400~600ms. 누르는 동안 시각적 진행 단서(확대, 하이라이트)와 햅틱을 준다. 손가락이 일정 거리 이상 움직이면 취소. 스크린 리더용 대체 동작 제공.
- 비슷한 것: 탭(짧게), 드래그(길게 누른 뒤 이동으로 이어진다).

### 스와이프 (Swipe)
- 무엇: 손가락을 한 방향으로 쓸어 넘기는 조작.
- 언제: 캐러셀, 탭 사이 이동, 카드 넘기기, 시트 닫기.
- 피할 때: 중요한 행동을 스와이프에만 두는 것, 가로 스크롤과 충돌하는 곳.
- 구현 주의: 거리 임계값 약 20~30%나 속도 임계값으로 확정, 미달 시 원위치로 스프링 복귀. 손가락을 따라오는 실시간 반응. 세로 스크롤 방향과 구분되도록 방향 잠금. 좌우 버튼 대안과 페이지 인디케이터.
- 비슷한 것: 밀어서 삭제(특정 행동에 묶인 스와이프), 가장자리 스와이프.

### 밀어서 삭제 (Swipe to delete)
- 무엇: 목록 항목을 옆으로 밀어 삭제나 보관 같은 행동 버튼을 드러내는 조작.
- 언제: 메일, 할 일, 알림 같은 목록에서 빠른 정리.
- 피할 때: 되돌릴 수 없는 삭제를 확인 없이 하는 것, 이것만이 삭제 수단인 경우.
- 구현 주의: 끝까지 밀면 실행, 중간까지 밀면 버튼 노출. 행동 색(삭제는 붉은색)과 아이콘과 글자를 함께. 삭제 후 되돌리기 [스낵바](feedback.md). 항목 안 다른 제스처(가로 스크롤)와 충돌 점검. 접근성을 위해 항목 메뉴(케밥)에도 삭제를 둔다.
- 비슷한 것: 스와이프(일반).

### 드래그 (Drag and drop)
- 무엇: 요소를 누른 채 움직여 다른 위치에 놓는 조작.
- 언제: 순서 변경, 칸반 보드 이동, 파일 업로드.
- 피할 때: 터치 화면에서 유일한 방법으로 쓰는 것. 긴 거리 이동.
- 구현 주의: 잡는 손잡이 아이콘(⋮⋮)을 보이고 영역 44px 이상. 드래그 중 요소를 들어 올린 모양(그림자, 약간 확대), 놓을 위치 표시선, 자동 스크롤. 키보드 대안(위아래 이동 버튼이나 메뉴)과 `aria-live`로 위치 변경 안내. 취소 방법(Esc, 제자리로).
- 비슷한 것: 길게 누르기(드래그 시작 동작).

### 핀치 (Pinch to zoom)
- 무엇: 두 손가락을 벌리거나 모아 확대·축소하는 조작.
- 언제: 사진, 지도, 지도형 도면, 큰 문서.
- 피할 때: 일반 UI 화면 전체(페이지 확대는 사용자가 브라우저에서 할 수 있게 막지 않는다).
- 구현 주의: 확대 범위(1x~5x 정도)와 경계에서의 탄성. 두 번 탭 확대와 `+ −` 버튼을 함께 제공. 웹에서는 `user-scalable=no`나 `maximum-scale=1`로 페이지 확대를 막지 않는다(접근성 위반).
- 비슷한 것: 두 번 탭.

### 두 번 탭 (Double tap)
- 무엇: 빠르게 두 번 탭하는 조작.
- 언제: 사진 확대·원래 크기, 좋아요(소셜 피드의 관례).
- 피할 때: 중요한 행동의 유일한 수단. 일반 버튼에 두 번 탭을 요구하는 것.
- 구현 주의: 두 탭 사이 간격 약 300ms 이내. 첫 탭의 동작이 지연되는 문제(두 번째 탭을 기다리는 시간)를 피하려면 첫 탭 동작과 충돌하지 않는 곳에만 쓴다. 눈에 보이는 버튼 대안.
- 비슷한 것: 핀치(같은 확대).

### 당겨서 새로고침 (Pull to refresh)
- 무엇: 목록 맨 위에서 아래로 당기면 내용을 새로 불러오는 조작.
- 언제: 피드, 메일함 등 최신 내용을 확인하는 모바일 목록.
- 피할 때: 자동으로 갱신되는 목록(실시간), 데스크톱 화면. 이 제스처가 브라우저의 자체 당겨서 새로고침과 충돌할 때.
- 구현 주의: 당기는 거리에 따라 인디케이터가 나타나고 임계값(약 60~80px)을 넘으면 새로고침. 진행 중 스피너를 보여 주고 끝나면 닫는다. 오류 시 재시도 안내. 웹은 `overscroll-behavior`로 브라우저 기본 동작 조정. 새로고침 버튼 대안.
- 비슷한 것: 무한 스크롤([navigation.md](navigation.md), 아래쪽으로 더 불러오기).

### 가장자리 스와이프 (Edge swipe)
- 무엇: 화면 가장자리에서 안쪽으로 쓸어 뒤로 가기나 메뉴 열기를 하는 조작.
- 언제: iOS의 왼쪽 가장자리 뒤로 가기, 안드로이드 제스처 내비게이션, 드로어 열기.
- 피할 때: 가장자리 영역에 스와이프할 앱 자체 요소(캐러셀, 슬라이더)를 두는 것. 시스템 제스처와 충돌한다.
- 구현 주의: 가장자리 약 20px 영역이 시스템에 예약되어 있다고 가정하고 앱의 가로 제스처 시작점을 안쪽에 둔다. 뒤로 가기는 시스템과 같은 결과를 내야 한다. 뒤로 가기 버튼도 화면에 둔다.
- 비슷한 것: 뒤로 가기([navigation.md](navigation.md)), 드로어.
