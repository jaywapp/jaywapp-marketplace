# 알림·피드백 (9종)

사용자 행동의 결과나 시스템 상태를 알리는 요소다. 선택 기준은 아래 표를 먼저 본다. 쌍 비교는 [confusable-pairs.md](confusable-pairs.md), 완료를 알리는 연출은 [indicators-completion.md](indicators-completion.md).

## 한눈에 고르기

| 상황 | 쓸 것 |
|---|---|
| 저장됨, 복사됨 같은 가벼운 확인 (되돌릴 필요 없음) | 토스트 |
| 삭제, 보관 같은 되돌릴 수 있는 행동의 결과 | 스낵바(되돌리기 포함) |
| 화면 전체에 해당하는 지속 안내 (점검, 오프라인, 약관 변경) | 배너 |
| 반드시 결정해야 계속할 수 있는 확인 (되돌릴 수 없는 삭제, 결제) | 모달 |
| 모바일에서 선택지나 부가 작업을 보여 줄 때 | 바텀시트 |
| 입력 칸 하나의 문제 | 인라인 오류 |
| 아이콘이나 용어에 대한 짧은 보충 | 툴팁 |
| 새 기능이나 숨은 조작을 처음 알릴 때 | 코치마크 |
| 읽지 않은 수나 상태 표시 | 뱃지 |

## 항목

### 토스트 (Toast)
- 무엇: 화면 위에 잠깐 떴다가 저절로 사라지는 짧은 알림. 눌러도 할 일이 없는 확인용.
- 언제: "복사했어요", "저장됐어요"처럼 결과만 알리면 되는 가벼운 성공 안내.
- 피할 때: 오류 원인 설명, 되돌리기가 필요한 행동, 반드시 읽어야 하는 정보. 이때는 스낵바, 인라인 오류, 모달.
- 구현 주의: 지속 시간 2~4초, 글이 길면 늘린다(글자 수에 따라 약 5초까지). 위치는 한 곳으로 고정(모바일은 하단 탭바 위나 상단, 데스크톱은 우상단이나 하단 중앙). 한 번에 하나만 보이고 쌓이면 대기열. `role="status"`와 `aria-live="polite"`로 스크린 리더에 읽힌다. 호버 중에는 사라지지 않게 한다.
- 비슷한 것: 스낵바(액션 버튼이 있고 한 번에 하나, 되돌릴 수 있는 결과에 쓴다).

### 스낵바 (Snackbar)
- 무엇: 화면 아래에 올라오는 한 줄 알림으로 오른쪽에 `되돌리기` 같은 액션 하나를 붙일 수 있다.
- 언제: 삭제, 보관, 이동처럼 되돌릴 수 있는 행동의 결과를 알리면서 취소 기회를 줄 때.
- 피할 때: 액션이 필요 없는 단순 확인(토스트), 놓치면 안 되는 오류(인라인 오류나 배너), 액션이 2개 이상일 때.
- 구현 주의: 지속 시간 4~10초(액션이 있으면 짧게 끝나지 않게 최소 5초 이상). 폭은 모바일에서 좌우 여백을 두고 거의 전체, 데스크톱에서는 최대 약 560px. 액션 버튼의 터치 영역 48px 이상. 키보드로 도달할 수 있어야 하며, 시간 제한이 있어 스크린 리더 사용자를 위해 `aria-live`로 알리고 마우스를 올리면 시간이 멈추게 한다. 다른 하단 요소(FAB, 탭바)와 겹치지 않게 위로 올린다. 되돌리기 전까지 실제 삭제를 미루는 방식이 안전하다.
- 비슷한 것: 토스트(액션이 없다).

### 배너 (Banner)
- 무엇: 화면이나 영역 위쪽에 고정되어 사용자가 닫거나 해결할 때까지 남는 가로 알림 띠.
- 언제: 오프라인, 점검 예정, 계정 인증 필요, 약관 변경처럼 지속적으로 알려야 하는 상태.
- 피할 때: 한 번 확인하고 끝나는 정보(토스트), 광고성 안내를 계속 띄울 때(방해가 되면 팝업과 같은 취급을 받는다).
- 구현 주의: 종류(정보, 성공, 경고, 오류)마다 아이콘과 색을 쓰되 색만으로 구분하지 않는다. 닫기 버튼 영역 44px, 주 행동은 1개. 긴급한 오류는 `role="alert"`, 일반 안내는 `role="status"`. 콘텐츠를 밀어 내리는지(레이아웃 이동) 위에 덮는지 정하고 한 방식을 유지한다.
- 비슷한 것: 배너 vs 팝업([confusable-pairs.md](confusable-pairs.md)), 인라인 오류(특정 입력 칸에 붙는다).

### 모달 (Modal dialog)
- 무엇: 화면 가운데 뜨고 뒤 화면을 막아 사용자가 응답해야 계속할 수 있는 대화상자.
- 언제: 되돌릴 수 없는 삭제, 결제 확인, 저장하지 않은 변경 폐기, 반드시 결정해야 하는 질문.
- 피할 때: 단순 안내(토스트), 긴 폼이나 탐색(별도 화면), 모바일의 선택지 목록(바텀시트), 첫 진입 직후 광고.
- 구현 주의: 제목 한 줄, 설명 한두 문장, 버튼 2개 이하(주 버튼을 오른쪽이나 아래에 둔다). 파괴적 행동은 버튼 라벨에 `확인` 대신 `삭제`처럼 행동 이름을 쓴다. 폭은 모바일에서 좌우 24px 여백, 데스크톱 약 400~560px. 열릴 때 포커스가 안으로 들어가고 Tab이 갇히며(`dialog`, `aria-modal`), Esc로 닫히고 닫으면 포커스가 원래 요소로 돌아간다. 뒤 화면 스크롤 잠금.
- 비슷한 것: 바텀시트(모바일에서 같은 용도를 덜 막는 방식), 모달 vs 바텀시트([confusable-pairs.md](confusable-pairs.md)).

### 바텀시트 (Bottom sheet)
- 무엇: 화면 아래에서 올라오는 패널. 선택지, 상세, 공유 같은 부가 작업을 담는다.
- 언제: 모바일에서 옵션 선택, 필터, 공유(공유 시트), 짧은 폼, 지도 위 상세.
- 피할 때: 데스크톱 넓은 화면(모달이나 팝오버), 긴 폼 전체(별도 화면), 오류처럼 반드시 읽어야 하는 알림.
- 구현 주의: 위쪽에 손잡이(너비 약 32~40px, 높이 4px)를 두고 아래로 끌어 닫는다. 높이는 내용에 맞추거나 절반, 전체 단계로 둔다. 모달형은 뒤에 스크림을 깔고, 비모달형(지도 시트)은 뒤 조작을 허용한다. 닫기 버튼도 별도로 둔다(제스처에만 의존하지 않는다). 하단 안전 영역 패딩, 키보드가 올라오면 위로 밀린다. 시트 확장 전환은 [motion.md](motion.md).
- 비슷한 것: 모달(화면 중앙, 더 강하게 막는다), 드로어(옆에서 나오는 이동 메뉴).

### 인라인 오류 (Inline error)
- 무엇: 문제가 생긴 입력 칸 바로 아래에 붙는 오류 문구.
- 언제: 폼 검증 실패. 어디가 왜 틀렸고 어떻게 고치는지 알려야 할 때.
- 피할 때: 폼 전체 제출 실패 같은 전역 오류(폼 상단 요약이나 배너), 입력 중간에 너무 일찍 나무랄 때.
- 구현 주의: 칸 아래에 붙이고 오류 색(대비 4.5:1)과 아이콘, 칸 테두리 변화를 함께 쓴다. 문구는 원인과 해결 방법("이메일 형식이 아니에요. @를 포함해 주세요"). `aria-invalid="true"`와 `aria-describedby`로 칸과 연결. 검증 시점은 포커스를 잃을 때나 제출 시. 오류가 여러 개면 첫 오류 칸으로 포커스 이동. 입력 칸 상태는 [inputs.md](inputs.md).
- 비슷한 것: 플레이스홀더 vs 라벨([confusable-pairs.md](confusable-pairs.md)과 연결된 입력 규칙).

### 툴팁 (Tooltip)
- 무엇: 요소에 마우스를 올리거나 포커스하면 나오는 짧은 설명 말풍선.
- 언제: 라벨이 없는 아이콘 버튼의 이름, 잘린 글의 전체 보기, 용어 한 줄 설명.
- 피할 때: 필수 정보(터치 기기에서는 호버가 없어 못 본다), 긴 설명이나 링크·버튼이 든 내용(팝오버), 모바일 중심 화면.
- 구현 주의: 글은 한두 줄. 호버 후 약 300~500ms 지연으로 표시, 포인터가 말풍선으로 옮겨도 유지, Esc로 닫힘. 키보드 포커스에도 나와야 하고 `aria-describedby`로 연결한다. 화면 경계에서 위치를 뒤집는다.
- 비슷한 것: 툴팁 vs 팝오버([confusable-pairs.md](confusable-pairs.md)), 코치마크(처음 한 번 먼저 알려 준다).

### 코치마크 (Coach mark)
- 무엇: 새 기능이나 숨은 조작을 가리키는 말풍선이나 강조 영역. 첫 사용 안내에 쓴다.
- 언제: 처음 방문 시 핵심 기능 1~3개를 짚어 줄 때, 새 기능 출시 직후.
- 피할 때: 첫 화면에서 5개 이상 연속으로 띄울 때(건너뛰어진다), 화면 자체가 설명이 필요할 만큼 복잡할 때(화면을 고친다).
- 구현 주의: 한 번에 하나씩 보여 주고 `건너뛰기`와 `다음` 둘을 둔다. 강조 영역 밖은 어둡게 하되 대상 요소의 실제 위치와 맞춘다(스크롤, 리사이즈 시 재계산). 본 뒤에는 다시 띄우지 않도록 상태 저장. 키보드와 스크린 리더로도 읽히게 한다. 온보딩 흐름에서의 위치는 [onboarding.md](onboarding.md).
- 비슷한 것: 툴팁(요청해야 나온다), 온보딩(앱 전체를 먼저 소개하는 화면 묶음).

### 뱃지 (Badge)
- 무엇: 아이콘이나 항목 모서리에 붙는 작은 점이나 숫자로, 새로운 것이나 읽지 않은 수를 알린다.
- 언제: 알림 수, 읽지 않은 메시지, 장바구니 개수, 새 기능 점.
- 피할 때: 상태를 설명하는 글자 라벨(칩), 모든 곳에 뱃지를 붙여 중요한 것이 묻힐 때.
- 구현 주의: 숫자 뱃지는 최소 지름 16~20px, 99를 넘으면 `99+`. 점 뱃지는 지름 8px 안팎. 색과 숫자 대비 4.5:1. 의미를 `aria-label`("읽지 않은 알림 3개")로 제공한다. 확인하면 사라져야 한다.
- 비슷한 것: 칩 vs 배지([confusable-pairs.md](confusable-pairs.md)), 평점 배지([ratings-share.md](ratings-share.md)).
